## 0. 一句话结论

**设计没有画大饼** —— 绝大多数承诺都落地了（含 E1–E6 极端场景四件武器、11 种格式、
分卷/加密/中文名/救援/诊断包）。真正的缺口集中在 **6 处**，其中 2 处直接影响用户：
**中文密码可能根本解不开**、**解压不能选输出目录**。

**另外两条"会在界面上骗人"的实现问题：**

- `src/preview.rs:322` → `encrypted: false` 是**硬编码**（注释写着"保守报 false"）。
  内容加密的 7z 在界面显示"不需要密码"，点开才炸。P4 密码流程直接依赖这个字段。
  → 修法小：遍历 `archive.blocks` 找 AES coder（`0x06F10701`）。
- `src/layout/zip.rs:41` → `DEFAULT_WINDOW = 1 << 20`（1 MiB 尾部窗口）。
  尾部垃圾超过 1 MiB 的包（自带样本 `E1_junk5m`）够不着，只能退化到全文件扫描；
  7z/zip 的 `--list` 从毫秒变成十几秒。→ 改成分块倒扫（64 KiB 块 + 20 B 重叠），小改动。

## 2. 实现比设计更好的地方（别改回去）

1. **缺分卷从"通报"变"可执行"**：设计只写"报告缺哪卷"，实现返回
   `detail{missing, found}`，界面直接说「缺这一块：卷.7z.003，已找到 2 块，下下来再拖进来」。
2. **引擎三级查找**：`YSHJY_BIN` → 同目录 → PATH（`gui/lib/engine.dart:216`）。
   设计假设"装到系统"，实际做出来发布包可免安装双击即用。
3. **引擎不出中文文案**：设计没提，实现把所有文案挪进 7 种语言包 —— 才有现在 7 语言。
4. **失败卡"翻译人话"**：拿 `looks_like` / `ext_mismatch` / size 拼出
   「名字写的是 .mp4，内容其实是 ZIP —— 这很可能就是伪装包」。竞品只是一张静态原因清单。
5. **密码重试零菜单跳转**：失败页内联输入框 + autofocus + 回车即重试；
   竞品（隐写者、ZArchiver）要 2–3 次键击才进到输密码。
6. **入口猜测**：解压完成按 setup/install/启动/.bat/.AppImage 猜首个入口并高亮 ——
   接住"解出一堆文件不知道点哪个"这个二次困惑，竞品都没有。
7. **批量失败清单就地铺开**：省一次点击（调研原本设计成 `[查看 2 个失败]` 二级页）。
8. **一键诊断包脱敏**（`--no-paths`）：调研只要求"复制诊断信息"。
9. **磁盘空间预检**：设计没写，实现加了（留 5% 余量，`--force` 可跳过）。

## 4. 竞品界面：还漏什么、哪里抄错

### 4.1 调研建议抄、界面还没做

- **解压前确认区**（`07:234-238`）：缺「输出到 [路径]」+「解压后：保留/移入回收站」。
  这是最大缺口——它同时卡住三条调研结论（Bandizip 路径对话框、安全默认三件套、
  回收站替代永久删除），且要引擎加字段。
- **密码框眼睛图标**（`07:383`「是标配，必须做」）：`home_page.dart:1260` 是裸
  `obscureText: true`，打错一个字符只能整段重输。
- **密码卡三件套**（`07:874-878`）：缺「近期密码 chips」（按成功次数排）、
  「☐ 不保存本次密码」。密码本存在 `~/.config/yshjy/passwords.txt` 但界面看不见内容。
- **试密码过程可视化**（`07:879-881`）：只有一句「需要解压码」，
  没有「正在试第 3/12 个」。大包试密码时进度条不动 → 用户以为卡死。
- **进度页缺速度与剩余时间**（`07:248` 明确说要超过 Bandizip）：现在只有
  文件名 + 已传/总量。
- **智能解压的"结果预告"与三模式开关**（`07:864-865`）：单文件预览页一个字都没提，
  用户点「开始解压」前不知道会多出 `movie/` 还是铺一地文件。
- **完成卡缺「复制解压方法给对方」**（`07:952-954`）：资源分享圈的真实动作没入口。

### 4.2 抄错了方向（调研明确说别这么干）

- **批量失败行让英文枚举裸奔**：`home_page.dart:782` 副标题用 `outcome.toLowerCase()`，
  用户看到 `failed` / `partial`；而单文件路径有 `_errText` 人话。调研 `07:180` 正是
  吐槽竞品把 `{e}` 直接抛给用户。→ 复用 `_errText` 按 `detail.code` 映射（小）。
- **失败/历史条目点了没反应**：批量失败行（`778-784`）不可点、无「在目录中显示」；
  历史页条目（`history_page.dart:102-121`）也没 onTap。调研 `07:135` 说
  "静默隔离让用户找不到"是反面教材。→ 加打开所在目录（中）。
- **第一屏三个入口**：`选择文件`/`选文件夹` 同级并排 + AppBar 一个 folder 图标
  （`561-567`）。调研 `07:921-923` 要求"只有一个最强入口"。→「选文件夹」收进溢出菜单（小）。
- **空状态把 10 个格式名当卖点**：`home_page.dart:871` 对新手是一串无意义符号
  （调研 `07:800`「用户对格式没概念」）→ 换成一句「认不出的也能试，拖进来就行」，
  格式列表移关于页（小）。

## 5. 建议的第 20 批排法

原计划：P5 设置可写 + P4 密码管理。建议改成：

```
1. P4 前置（都是小改动，但决定密码功能有没有意义）
   · 密码多编码 UTF-8 → GBK → UTF-16LE        ← 最要紧
   · 7z 条目加密标记如实上报（现在硬编码 false）
   · 密码框加眼睛图标
2. P2b 封面分离（用户明确要求过，DESIGN §3）
3. P4 本体（近期密码 chips / 不保存本次 / 试到第几个）
4. P5 设置可写 + 输出目录 + 原包处理（on_done: 保留/回收站）
5. 打包页 10 个开关（如果一天做得完，否则拆到第 21 批）
```

理由：密码功能要是密码本身解不开（中文/GBK），做再多界面也白做；输出目录是调研里
被三条结论共同卡住的点，且改动会动协议，越早越好。
