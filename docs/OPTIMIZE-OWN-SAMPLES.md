## 二、🔴 真缺口：zip 分卷（`.zip` + `.z01`）没拼起来

**样本**：`C12_split.z01`（307,200 B）+ `C12_split.zip`（103,588 B），一个完整的 5 文件分卷包

| 谁 | 结果 |
|---|---|
| 7z | ✅ `Volumes: 2` → **5 files, 3 folders** |
| 我们 `--list C12_split.zip` | ⚠️ 「中央目录坏了，已按文件头重建清单（**1 项**）」 |
| 我们 `--list C12_split.z01` | ❌ 「这不是压缩包」 |
| 我们 `--test C12_split.zip` | ❌ 「这不是压缩包（没找到可识别的压缩数据）」 |

**好消息：它自己把根因打出来了（诊断信息很完整，没白写）**

```
[NOT_ARCHIVE] 分卷里的中央目录没找到（是不是缺了一块？）
reason=base_is_not_local_header
base=307200  found=1e4007fd
（推算的 base=307200 处不是 PK03 04（cd_at=410214, cd_offset=103014））
```

- 合并流总长 410,788；中央目录在 410,214；CD 里记录的偏移 103,014
- 推算出来的流起点 `base = 410214 − 103014 = 307200` —— **这个数是对的**（正是第一块的字节数）
- 但校验要求「base 处必须是 `PK0304`」→ **分卷的续块开头本来就不是 local header，它是上一块数据的延续**
- 于是判定失败 → 降级到「按文件头重建」→ 只抢救出 1 项

**这是「校验规则用错了地方」**：`base_is_not_local_header` 这个检查在**单文件**场景是对的，
在**分卷流**场景不适用。

**参考项目现成解法**
- 我们自己 `src/unpack.rs:27` 就抄了 7-Zip 的设计注释：
  「分卷由 handler **反向索取**（`IArchiveOpenVolumeCallback`），opener 不必懂各格式的卷名规则」
  —— 也就是说**卷的拼接不该在偏移校验这一层做判断**，应该让 handler 拿到双向 seek 的流自己算。
- 7-Zip 侧实现在 `CPP/7zip/Archive/Zip/ZipIn.cpp`（分卷 + 头位置推算）
- 我们现有实现：`src/job.rs:692` 认卷名 → `src/unpack.rs` 拼流 → `src/layout/zip.rs` 定位 CD

**建议动作**（P8 才动手，现在只记）
分卷流（`Shape::Volumes`）走到 CD 定位时，跳过「base 处必须 `PK0304`」这条断言，
改用「`cd_at − cd_offset` 落在卷边界上」作为判据；对不上再降级救援。

**为什么要紧**：分卷 zip 在国内网盘场景**很常见**（超过 2G 的包常被 split）。
而且 `tests/` 里**没有任何断言跑我们的引擎验过 C12** ——
`make_samples.py:1011` 只拿 `7z t` 当验证工具。这就是典型的「假绿温床」：
样本生成了、7z 验过了、我们的引擎一次没跑过。

## 三、🟡 我们比 7z 强的 5 个（要守住，别被「统一」掉）

| 样本 | 我们 | 7z |
|---|---|---|
| `D2b_prefixed_2355200.zip` | 定位到偏移 2,355,192，「✅ 校验通过」 | ❌ **Cannot open the file as [zip] archive** |
| `C4_plain.tar.gz` | 穿透到 tar 里，列 **5 个文件** | 只认 gzip 层，**1 files** |
| `C5_plain.tar.xz` | 同上 5 个 | 1 files |
| `C6_plain.tar.zst` | 同上 5 个 | 1 files |
| `C7_plain.tar.bz2` | 同上 5 个 | 1 files |

- **D2b**：包前面塞了 2.3 MB 垃圾，7z 直接认不出，我们按全文件扫描找到真位置 —— 这就是「武器①」的价值。
- **tar.xxx 穿透**：用户要的是「里面有几个文件」，gzip 层只是外壳。我们列 5 个是对的，7z 列 1 个是它的口径。

→ 这 5 条建议写进 `REFERENCE-INDEX` 或代码注释，标 **B 类（有意不抄）**。
