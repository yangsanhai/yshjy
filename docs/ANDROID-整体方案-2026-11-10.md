# 安卓版（APK）· 整体方案

> 2026-11-10 立。**本文是"怎么干"的落地版**；`docs/ANDROID-PLAN.md`（2026-11-05）保留为"为什么这么定"的设计依据，两者冲突时以本文为准。
> 触发：老板问「安卓版要装什么」→ 发现现有界面是桌面形态，追问「参考项目怎么解决的」。
> 本文所有参考项目结论都是**读过代码/看过截图**得出的，标了文件位置；数字是当场数出来的。

## 0. 结论摘要（一屏看懂）

| 问题 | 答案 |
|---|---|
| 要不要重做界面 | **要**。11,022 行 Dart 里约 2,700 行逻辑能复用，页面层（约 6,000 行）是桌面形态，手机必须重排 |
| 参考项目怎么解的 | **rustdesk：一套逻辑 + 两套界面**（`common/` 16,298 行共享，`desktop/` 22,862 行、`mobile/` 10,445 行各写各的，`main.dart` 里 `if (!isDesktop) runMobileApp()` 直接分岔） |
| 引擎要改多少 | 不大：C ABI **9 个导出已经能干活**（含后台任务 + 事件回调 + 取消），主要是 27 处平台假设（`/proc` 13、`/sys` 4、外部命令 10）加 `cfg(target_os="android")` |
| 界面要写多少 | 新建 `gui/lib/mobile/`，约 **4,000–5,000 行**；桌面 `pages/`（1990 行的首页那套）**一行不动** |
| 打包页 | **不做**（手机不需要"伪装成视频"，且依赖 ffmpeg）→ 直接省掉 1,220 行移植 |
| 总工期 | **7–9 天**（环境 0.5 / 引擎 1 / 桥接 1 / 存储 1–1.5 / 界面 3–4 / 发布 0.5–1） |
| 止损点 | 批 2「第一块 `.so` 能在真机跑起来」，不过就停下来换方案 |

## 1. 参考项目怎么解的（实证）

### 1.1 rustdesk —— Flutter + Rust，安卓真上架过，架构就是答案

`refs/upstream/rustdesk/flutter/lib/` 的实际分层（当场数的）：

| 目录 | 文件 | 行数 | 是什么 |
|---|---|---|---|
| `common/` | 30 | **16,298** | 全平台共享：主题、控件、协议、状态 |
| `models/` | 32 | **19,684** | 模型/状态层 |
| `desktop/` | 36 | **22,862** | 桌面界面 |
| `mobile/` | 17 | **10,445** | 手机界面（`pages/` 7 个页面 + `widgets/`） |
| `utils/` | 8 | 1,127 | 小工具 |
| `native/` | 3 | 134 | FFI 绑定 |

分岔只有两行（`lib/main.dart` 第 45 行）：

```dart
if (!isDesktop) {
  runMobileApp();          // 直接换一个 App 根
}
```

判定在 `lib/common.dart`：`var isMobile = isAndroid || isIOS;`

**要点（我们要照抄的三条）**：
1. **不是"一套界面加一堆 if"**，是两套并行目录，共享 `common/` + `models/`。手机界面只占桌面的 46% 体量 —— 因为手机不需要那么多专业功能。
2. 页面级也是各写各的：`desktop/pages/settings_page.dart` 和 `mobile/pages/settings_page.dart` 同名不同文件。
3. 平台差异集中在 `common/common.dart` 的 `isDesktop/isMobile` 判定 + 主题里 `(isDesktop || isWebDesktop) ? ... : ...` 的**触屏/鼠标分叉**（水波纹、按钮内边距、对话框按钮位置）。

### 1.2 localsend —— 安卓分区存储的标杆（照抄 SAF 三步）

| 它在干什么 | 文件 |
|---|---|
| Flutter 官方 `file_selector` 选目录，拿回 `content://…/tree/…` | `app/lib/util/native/file_picker.dart` |
| tree URI 反解成真实路径（`primary:Documents` → `/storage/emulated/0/Documents`） | `packages/localsend_isolates/lib/util/content_uri_helper.dart` |
| 写 SAF 文件：Kotlin 建文件 → 取**可写 fileDescriptor** → 往里写 | `android/.../MainActivity.kt` + `file_saver.dart` |
| 自研 `FastDocumentFile`：一次查询拿全字段（官方 `DocumentFile` 逐字段查，解压写上千文件时开销是真实的） | `android/.../FastDocumentFile.kt` |

### 1.3 ZArchiver —— 手机解压 App 的交互范式（`refs/ui-reference/ZArchiver/`）

看图中的实际做法：
- **主界面 = 文件列表**（路径栏 + 搜索 + 视图切换 + 右上溢出菜单），不是"拖入区"
- **点文件 → 底部动作单**：`View` / `Extract here` / `Extract to ./<Archive name>/` / `Extract…` / `Test` / `Compress…`
- 长按 → 多选；`⋮` → 全局长操作

**对我们的启示**：桌面那套「拖入 → 预览 → 解压」到手机上要变成「**选择/分享进来 → 预览 → 一键解压**」，并且**常用动作要下沉到动作单**（解到哪、改不改名），不要做成一排按钮。

### 1.4 其它两条（已核实，直接定调）

- **hiddify**：头文件是构建产物（`go build -buildmode=c-archive` 顺带产 `.h`），我们 `ffi/include/yshjy.h` 是**手写的第二份真源**，做安卓前这次顺手治掉（见 §4.4）。
- **flutter_rust_bridge 不用**：那是"从 Rust 侧生成桥接层"，适合本来没有 C 接口的引擎；我们 `crate-type` 里已经有 `cdylib` + 9 个 `extern "C"`，用 **ffigen** 读 `.h` 生成绑定更直接（`docs/ROADMAP.md` §6 也把 frb 列进"明确不做"）。

## 2. 我们的架构（三层）

```
┌─ 引擎（Rust，全平台一份）  E:\yshjy-1.0.0-20261108\src\
│    lib.rs + 各模块；加 cfg(target_os="android") 分支，不复制代码
├─ 桥（C ABI + ffigen）  ffi/src/lib.rs → libyshjy.so → gui/lib/gen/
│    已有：yshjy_request（同步）/ yshjy_job_submit（事件回调 + 取消）/ yshjy_job_wait
└─ 界面（Flutter，一套逻辑 + 两套呈现）
     gui/lib/common/    ← 从现有非页面文件抽出来：l10n / entry_tree / format / humanize /
                            pack_naming / history_store / app_settings / engine / transport
     gui/lib/desktop/   ← 现有 pages/ 与 app_shell 原样搬入，行为不变（**不重写**）
     gui/lib/mobile/    ← 新建：pages/ widgets/ mobile_shell.dart
```

**和现状的差别**：现在所有东西都在 `gui/lib/` 平铺（`pages/` + 若干根文件）。改造只是**移动文件 + 改 import**，不改逻辑 —— 这一步单独一批做，跑一遍 `flutter test` 确认桌面没坏，再开始写手机界面。

**为什么不用"响应式一套界面"**：`home_page.dart` 1990 行 + 15 个子视图约 2,300 行，里面大量宽屏三栏假设；就地加 `if (窄屏)` 最容易把你 11-10 刚验收的桌面版改坏。两套目录的代价是重复代码，收益是**桌面零回归**、手机可以放开手脚重排（这也正是 rustdesk 的选择）。

## 3. 引擎改造清单（精确到文件）

| # | 问题 | 位置（实测） | 改法 |
|---|---|---|---|
| 1 | 调外部命令会失败 | `Command::new` **10 处**：`extract_stream.rs`、`flush.rs`、`seek.rs`、`pack/mod.rs` | 逐个加 `cfg`：安卓上没有 `sync`/`7z` 这类外部程序；`flush.rs` 的 `sync` 改进程内 `libc::sync()` 或文件级 `fsync` |
| 2 | `/proc`、`/sys` 探测 | `/proc/` **13 处**（`flush.rs`、`hardware.rs`）、`/sys/` **4 处**（`api.rs`、`hardware.rs`） | 安卓直接返回「不适用」：磁盘类型（机械/固态）、落盘检验在手机上无意义 |
| 3 | TUI 依赖拖进 lib | `crossterm` 3 处、`indicatif` 16 处、`comfy-table` 1 处（全在 `main.rs`，安全）；`dialoguer` **15 处**（`cli_spec.rs`、`main.rs`、`pick.rs`） | `Cargo.toml` 把 TUI 依赖移进 `[target.'cfg(not(target_os = "android"))'.dependencies]`；`pick.rs`/`cli_spec.rs` 用 `cfg` 隔开。Cargo.toml 已有 `[target.'cfg(windows)'.dependencies]` 的先例，照写 |
| 4 | `zstd` 要 C 编译器 | `Cargo.toml` 的 `zstd`（`zstd-sys`） | 用 NDK clang 编（cargo-ndk 自动处理）；或安卓关掉打包/压缩相关 feature（手机不打包） |
| 5 | 前台服务/被杀 | 无（新增） | 见 §7 |

**判据**：编 `--lib`（不是 bin）时这些依赖不参与 —— 现在 `Cargo.toml` 是无条件依赖，安卓上会直接编不过，必须先改。

## 4. 桥接方案

### 4.1 C ABI 现状（够用，别重造）

`ffi/src/lib.rs`（299 行）已导出 9 个函数：

```c
uint32_t yshjy_abi_version(void);
char *yshjy_version(void);
char *yshjy_hello(void);
char *yshjy_request(const char *json);          /* 阻塞到任务结束 */
YshjyJob *yshjy_job_submit(const char *json, yshjy_event_cb cb, void *user);
int32_t yshjy_job_cancel(YshjyJob *job);
char *yshjy_job_wait(YshjyJob *job);            /* 阻塞；可重复调用 */
void yshjy_job_free(YshjyJob *job);
void yshjy_string_free(char *s);
```

**关键发现**：进度事件 + 取消**已经齐了**（`job_submit` 带回调），不需要改 ABI。

### 4.2 `FfiTransport` 怎么接（不改 `EngineClient` 一行）

现有接口 `EngineTransport` 只搬「整行 JSON」，所以实现就是**把每一行请求包成一次 job**：

```
writeLine(json)
  → 解析出 cmd
  → yshjy_job_submit(json, cb, user)      // cb 用 NativeCallable.listener（dart:ffi）
  → cb 每来一条事件 → 塞进 stdoutLines（一行一条 JSON）
  → 另起 Future 等 yshjy_job_wait → 补最后一条 {"ok":...} → yshjy_job_free
  → 返回的 Job 句柄存起来，kill()/cancel 时用 yshjy_job_cancel
```

`hello`/`list` 这类同步命令走 `yshjy_request`（少一次线程）。**依据**：`engine.dart` 约定"传输层不讲协议"，所以这层适配足够，`EngineClient` 与全部页面逻辑都不用改。

### 4.3 `.so` 落地

```
cargo ndk -t arm64-v8a -t armeabi-v7a -o gui/android/app/src/main/jniLibs build --release
# 产出 jniLibs/arm64-v8a/libyshjy.so（armeabi-v7a/x86_64 同理）
```

Dart 侧 `DynamicLibrary.open('libyshjy.so')`；用 ffigen 读 `ffi/include/yshjy.h` 生成 `gui/lib/gen/yshjy_bindings.dart`（**生成物进 .gitignore**）。

**16 KB 页对齐**（Android 15 起、2025-11-01 后 Google 强制）：NDK r28 的 linker 默认合规，验收命令：

```
readelf -l libyshjy.so | grep LOAD     # 期望 align 0x4000
```

### 4.4 顺手治掉的老账

`ffi/include/yshjy.h` 是**手写的第二份真源** —— `lib.rs` 加了导出、忘了改头文件，不会有任何报错。这次做安卓前：**用 `cbindgen` 从头文件反向校验**（或干脆由它生成头文件，`lib.rs` 当唯一真源），并加一条测试：9 个符号名必须与头文件逐条对上。

## 5. 存储方案（三条路，按 `ANDROID-PLAN.md` §4.2 的结论细化）

| 方案 | 做法 | 代价 | 我们的取舍 |
|---|---|---|---|
| **A 私有目录** | 解到 `getExternalFilesDir()`，零权限、立刻能写 | 多一步"导出"；卸载 App 连文件一起删 | **默认走 A**（装上就能用，不吓人） |
| **B 所有文件访问** | `MANAGE_EXTERNAL_STORAGE` + 跳系统设置页勾"允许管理所有文件" | 权限文案劝退；各 ROM 路径不同 | **做成设置里的开关**，默认关；开了才能解到任意目录 |
| **C MediaStore** | `ContentResolver.insert(Downloads)` + `RELATIVE_PATH`，零权限写 `Download/子目录/` | 引擎要支持写 fd；1200 个文件 = 1200 次 insert | **只做"导出到下载"**这一个动作 |

**引擎侧要开的两个口子**（按 §4.3 排期）：
- **输入吃 fd/流**（必需）：SAF 给的是 `content://`，`dart:io` 直接开会抛 `PathAccessException`。`src/io/blockcache.rs` 早就是为"只能顺序读的源"写的，正好用上。
- **输出写 fd**（只有走 C 才需要）：`src/io/atomic.rs` 的 `.yshjy-part` 中间态要保留。

## 7. 权限、系统集成、合规

| 项 | 要求 | 备注 |
|---|---|---|
| `MANAGE_EXTERNAL_STORAGE` | `manifest` 声明 + `ACTION_MANAGE_ALL_FILES_ACCESS_PERMISSION` 跳设置页 | 只在用户开 B 开关时才申请，别一启动就弹 |
| 前台服务 | `foregroundServiceType="dataSync"` + `FOREGROUND_SERVICE_DATA_SYNC` | **Android 14 漏了类型直接崩**；Android 15 起 dataSync 有 6 小时上限 → 长任务要能续跑 |
| 通知 | 进度通知 + 完成通知（Android 13+ 要 `POST_NOTIFICATIONS` 运行时授权） | 现有 `notify.dart` 65 行要加安卓分支（现在走 `notify-send`） |
| 16 KB 内存页 | NDK r28 + 上面的 `readelf` 检查 | 不合规的新设备装不上或崩 |
| `targetSdk` | 36（Flutter 3.47.8 默认） | 商店/侧载都按这个最省事 |
| 最小 SDK | 24（Android 7.0） | 覆盖绝大多数在用设备 |
| ABI | `arm64-v8a` 必出；`armeabi-v7a` 覆盖老机（各 +4~6 MB）；`x86_64` 仅模拟器 | 用 `--split-per-abi` 分别出包 |
| 签名 | 自签 keystore，**生成一次、永久用**，备份两份 | 换签名 = 覆盖安装不上 |

## 9. 风险与回退

| 风险 | 触发信号 | 应对 |
|---|---|---|
