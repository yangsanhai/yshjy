## 3. 分批计划（每批一个提交，可单独回滚；做完一批就实测+写文档）

### L1 · RAR 彻底修（最高优先：真人一用就撞）
- **分卷支持**：改用 `rars::extract_volumes_to(&[Archive], …)`（0.11 已提供多卷流式 API）
- **去 256 MiB 上限**：改用 `Archive::extract_to`（流式写盘），安全限额改用 `ReaderOptions` 的
  `max_member_output_bytes` / `max_total_output_bytes` / `max_reader_workspace_bytes`，仍防炸
- **顺带补时间戳**：流式 API 的 `ExtractedEntryMeta` 带 `modification_time()`，把「RAR 没原始时间」
  这个老取舍一起做掉
- 验收：4 卷 RAR5 实测解出 5000 B 且 sha256 与 unrar 一致；>256 MiB 的 RAR 能解；
  13 个 RAR fixture 全过；`cargo test` 不退

### L2 · 文案与五态审计（D21 + X4/X5）
- 建 `diagnostic → 中文人话` 映射表，**缺文案的码一律不显示原始码**
- 安全拒绝单独一类：「包里有不安全的路径，已跳过（可能是恶意包）」而不是「数据丢了」
- 五态（空/加载/成功/失败/部分成功）逐页过，先补「失败」「部分成功」
- 验收：扫一遍所有 `ErrorCode` / `DIAGNOSTIC`，命中率 100%；菜鸟读得懂

### L3 · 文件属性与符号链接（X3）
- 安全的相对符号链接**建出来**（`S_IFLNK`），绝对路径/指向目标外的明确拒绝并中文说明
- 权限位、空目录已达标（回归保住）；顺带补硬链接策略
- 验收：带 3 个 .so 链接的 tar.gz 解开后 `diff -r` 与原目录一致

### L4 · 中间层加固
- 新增 `PACK_PROGRESS` 事件（阶段 + 已写字节），界面打包页接上
- 协议契约测试：10 个命令的请求/响应 golden JSON（`tests/contract/`）
- `caps` 如实：新增 `rar_volumes` / `pack_progress` 等能力位，前端按位显示
- 验收：契约测试全绿；打 2 GB 包时界面有进度不假死

### L5 · Linux 桌面集成
- Nautilus 右键菜单脚本（`~/.local/share/nautilus/scripts` + deb 提供）
- 默认打开方式：把常见压缩 MIME 的候选位次提到 File Roller 前面（debian `mime` 配置）
- 托盘/后台：按需（先做「解压中最小化到托盘」还是不做，L5 开工时定）
- 验收：右键压缩包出现「用杨三海解压」；文件管理器双击能选到我们

### L6 · 界面收口
- D4 Del 键删队列条目 / D5 批量单独取消 / D6 拖动目录文案 / D8 结果带 detail
- 首屏单一入口收口（AUDIT-17b #15）
- 验收：键盘能手不摸鼠标完成「选包→解压→看结果」

### L7 · 一条命令的回归网 + 出包
- `tests/all.sh`：语法 + `cargo test` + `clippy -D warnings` + 6 探针 + `flutter test`，
  默认 <60 秒跑完；`--slow` 才跑 RAR 分卷/大包样本
- 版本递进 `0.9.25-c` 起，每批递增；`build-deb.sh` 自查照旧
- 验收：改一处 → 一条命令 → 30 秒知道有没有砸坏东西

## 4. 「Linux 完全版」验收定义（做完 L1–L7 才算）

1. 网盘常见 RAR：单卷 / 分卷 / 加密 / 大于 2 GB，全部能解（含中文密码）
2. tar 系列里符号链接、权限位、空目录、时间戳都能还原；不安全条目拒绝且有中文说明
3. 任何失败路径，用户看到的是中文人话 + 下一步建议，**没有一处原始码**
4. 协议 10 个命令有契约测试；打包有进度事件
5. `tests/all.sh` 一条命令全绿（<60 s）
6. deb 装完：桌面菜单、右键菜单、默认打开方式、完成通知、卸载干净
7. 真实用户（3–5 人）试跑无「看不懂/不敢再用」

## 8. 待观察（本轮发现、**留到以后**的问题，不跑偏）

- GUI 侧目前还没接文案表与打包进度（N1/N2 就是收这个）
- zip 格式里的符号链接（不是 tar）没实测；本轮只修了 TAR 那条路
- RAR 现在能拿到 `file_time` 了，修改时间还没还原（可以做，非阻塞）
- 打包路径只有「普通压缩」接了进度；伪装 / 自解压路径的进度还没接
- 缺卷判定对 RAR 的「最后一卷没下完」还判不出来（只有中间断卷能判）
