## 1. 判定标准：什么叫「完整」

以 `docs/UI-SPEC.md` 的 **14 个状态**为验收底线 —— 每个状态都要在界面上有对应设计，
不是只有顺利路径。再加三条来自竞品调研的硬标准
（`refs/analysis/07-竞品界面调研.md` 第 12 章）：

1. **失败必须可执行**：每个失败原因配一个按钮（补分卷 / 输密码 / 打开原目录 / 复制诊断）
2. **完成必须说清数字**：成功几个、失败几个、用时、产出多大
3. **密码永不落屏**：不明文打印试的密码（v2 的反面教材：`🔐 Trying password: 123456`）

## 3. 计划项

### P1 · 批量队列（S13）【大】
- **现在**：一次只能处理一个包（CLI 早就能批量，界面没接）
- **参考**：
  - Sunpack 完成通知（§9.1 `f08.png`）：`解压完成 / 48 个压缩包成功，用时 4 秒 / [打开输出目录]`
  - v2 汇总表（§1.1 `print_final_completion`）：用时 / 档案数（成功·失败·跳过）/ 文件数 / 输出位置
  - ZArchiver 工具栏形变（§4.2）：执行中工具栏原位变进度条，不是全屏模态
- **做法**：
  - 协议加 `scan`：输入路径列表 → 展开目录、归并分卷、只留候选，返回 `[{path, kind, size, volumes}]`
  - 协议加 `batch`：任务列表 → 逐个跑 `job::run_job`，每个任务发 `task_start/task_done`
  - GUI：解压页加「队列」区（每行：文件名 / 徽章 / 状态 / 进度 / 取消）
  - 完成卡按 Sunpack 三段式：`✅ 完成 · 48 成功 / 2 失败 / 用时 4 秒` + `[打开输出目录] [查看失败]`
- **验收**：拖入 10 个包（含 1 组 5 块分卷）→ 只产生 6 个任务（分卷合并）→ 逐个执行 →
  完成卡数字与实际一致 → 失败项点开有原因 + 动作
- **依赖**：无（引擎侧 `batch.rs` 已有逻辑，只需协议暴露）

### P2 · 智能解压（三条规则 + 把规则告诉用户）【中】
- **参考**：Bandizip 智能解压（§3.1 中文文案「分析压缩包结构来自动选择目标路径」）+
  OnlyUnzip 三模式（§9.2）
- **规则**（照抄 Bandizip）：
  1. 包内只有一个文件 → 解到当前位置
  2. 包内所有文件都在**同一个顶层文件夹**里 → 解到当前目录，复用该文件夹名
  3. 否则 → 新建 `<包名>/` 放进去；重名则 `<包名> (2)`
- **做法**：引擎侧已有部分逻辑（`out_dir` / `conflict`），补「顶层公共目录」判定；
  GUI 在解压前确认卡写灰字：`将创建「movie/」文件夹（包内是多个散文件）`，可点切换
- **验收**：三种结构的样本各一个，输出目录结构符合规则；确认卡文案与实际一致
- **依赖**：P1 之后做（同一条链路上）

### P3 · 失败卡可执行化（S9）【中】
- **现在**：失败页只有一句人话 + 「复制错误详情 / 生成诊断包」
- **参考**：v2 的「可能原因清单」（§1.3）→ 升级为**按钮**；调研第 12 章 ①
- **做法**：
  - 缺分卷：引擎补 `MISSING_VOLUME` 的 `expected` / `found` 字段 → 界面显示
    `缺 movie.part1（已找到 part2–5）` + `[补下载后重试]`
  - 密码：`PASSWORD_REQUIRED/WRONG` 已带已试数量 → 显示 `已试 12 个密码均失败` + 输入框
  - 损坏：`[复制诊断信息] [打开原目录]`
  - 一定要有一行：`原文件没动（未被删除）`
- **验收**：造 3 个样本（缺卷 / 加密 / 截断）→ 每个失败页都有对应原因 + 至少一个可点动作

### P2b · 封面分离：把伪装包里的视频/图片也拿出来（S7 增强）【中】

- **为什么必须做**：用户设计时就明确要求过（`DESIGN.md` §3「剥离封面 / 显示文件」，
  当时已实测：切出的 115MB 用 ffmpeg 解码 60 秒零错误）。但实现只做了**打包侧**的
  `cover_size`；`--extract-cover` 一直挂在 `CLI-SPEC.md` §3.6「待实现」里 ——
  于是解压完只看到压缩包里的文件，用户想保留的完整 mp4/图片拿不到。
- **现状数据**：伪装包 = 封面区 + 压缩层。定位阶段**已经**算出压缩层真实起点
  （真实包 `lvIesSotSDRhnZfL_1.mp4.zip` 是 119,248,031），封面区就是 `[0, 起点)`，
  长度 ≈119 MB，与 DESIGN 里实测的 115.7 MB 对得上 —— 不用重新解析容器。
- **做法**：
  1. 引擎：`extract` 成功后按结构切出封面区，写成独立文件
     （尾部模式的包切开头段；开头模式的包切末尾段；按原扩展名 `.mp4/.png`）。
     命名 `原文件名.封面.mp4`，**绝不覆盖原包**
  2. 可选：系统有 ffmpeg 时 remux 修 moov 索引（没有就跳过，不报错、不成为硬依赖）
  3. 协议：`extract` 结果加 `cover: {path, size, kind}`（只在真切出时出现）
  4. 界面：完成卡多一行「🎬 视频已分离：xxx.mp4（119 MB）[打开]」；
     CLI 同步实现 `--extract-cover`（只剥封面、不解压）
- **验收**：两个真实包（8.7GB / 5.9GB）解压后都多出可播放的封面文件；
  `ffmpeg -v error -i 封面.mp4 -t 60 -f null -` 零错误；原包 SHA-256 不变（只读不写）；
  封面是图片的样本也要出图。

### P4 · 密码管理（S4）【中】
- **参考**：OnlyUnzip 密码优先级（§9.2 原文五档）、ZArchiver 密码框眼睛图标（§4.1）、
  论坛用户要的「近期密码列表 + 不保存本次密码」（§9.4）；v2 明文泄露是反面教材（§1.4）
- **做法**：
  - 协议加 `passwords`：返回密码本条目（**打码 + 成功次数**，不返回明文）
  - 试密码时发事件 `password_try { index, total }` → 界面 `正在尝试第 3/12 个密码…`
  - 密码框加眼睛图标；加 `☐ 不保存本次密码` 复选框
  - 密码本按成功次数排序（OnlyUnzip 的优先级照搬，除了「虚拟密码」我们不做）
- **验收**：加密包 → 界面显示「第 N/M 个」而不是密码明文；成功后密码本次数 +1；
  勾了不保存 → 文件里确实没写
- **依赖**：`config` 只读命令（P5 的一部分）

### P5 · 设置可写 + 界面多语言（S1 引导附）【大】

- **做法**：

  - GUI：设置页变成真控件（语言下拉 / 并发 / 默认输出 / 重名策略 / 压缩比 / 可执行提醒 /

  - 界面 i18n：Dart 侧抽 `l10n`（先 zh-CN + en-US 两套，其余等引擎语言包对齐）
- **验收**：改「并发 = 4」→ 重启引擎后 `--show-config` 显示 4；切英文 → 全界面英文，
  包括错误人话；切回中文正常

### P6 · 菜单栏 + 快捷键 + 拖放增强（S1、S14）【中】

### P12 · 全平台（Windows / macOS / Android / iOS）【大 · 最后】

- **平台顺序（用户 2026-10-17 明确「全平台都要做」）**：
  Linux（当前开发/测试机）→ Windows → macOS → Android → iOS
- **参考**：`07-竞品界面调研.md` 第 11 章 10 条建议（ZArchiver 骨架 + 我们的一键按钮）
- **前置（建议第 21 批先做，各半天，不影响桌面，越晚越贵）**：
  1. `Cargo.toml` 加 `[lib] crate-type = ["rlib", "cdylib", "staticlib"]`
     —— 现在产不出 `.so`/`.a`，FFI 无从谈起
  2. Dart 抽 `EngineTransport` 接口，把现在的 `Process.start` 装进 `ProcessTransport`
     —— 否则界面死绑子进程，iOS 上永远跑不了
- **Android**：可复用 `ProcessTransport`（引擎随包分发）；`flutter_rust_bridge` 是更优解；
  存储走 SAF，随机定位按 `ARCHITECTURE.md` F1 的三档方案
- **iOS**：子进程**物理不可用**（iOS 禁止 fork/exec 任意可执行文件）→ 必须 `FfiTransport`
  （静态库进 Xcode）；文件必须经 document picker 导入沙箱再解，输出到沙箱后分享
- **桌面**：Windows / macOS 各补构建链；路径、回收站、内存与磁盘探测按平台分支（DESIGN §18.3）
- **验收**：每个平台都能安装/双击启动 → 解一个伪装包 → 出一份诊断包
- **不做**：不做广告、不做在线破解（合规红线）

## 6. 明确不做（边界，别再来问）

- 不联网、不上传、不做云密码同步（解优2 的云密码是付费点，但我们红线是不联网）
- 不做密码爆破 / 不内置常见密码表（`config.rs` 注释里已写明删掉 `try_common` 的原因）
- 不做常驻后台自动解压（Sunpack 的 watch 模式：桌面端收益低、权限风险高）
- 不做 Windows 右键菜单的那种「解压至此/智能解压至此」多级菜单（Linux 下桌面环境不统一）
