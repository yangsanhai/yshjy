## 阶段 1：要做（核心功能优先）

| # | 项 | 为什么（用户能感觉到什么） | 验收标准 |
|---|---|---|---|
| 1 | **协议契约测试**：10 个命令的请求/响应 golden JSON（`tests/contract/`） | 以后改引擎不怕悄悄改坏界面——界面读的字段一被改就红 | 契约测试全绿，且故意改坏一个字段能被测出来 |
| 2 | **`caps` 能力位如实**：补 `rar_volumes` / `pack_progress` 等 | 界面能按位显示「这个版本支持啥」，不会画个按钮点了没反应 | 老版本引擎不报的位，界面自动隐藏对应功能 |
| 3 | **伪装 / 自解压打包也报进度** | 现在只有普通压缩有进度条，打大伪装包还是死的 | 打 2 GB 伪装包，进度条在动 |
| 4 | **RAR 还原修改时间** | 解出来文件的日期变成现在，找东西不方便 | 解开后 `ls -l` 时间与原包一致 |
| 5 | **RAR「最后一卷没下完」判得出** | 现在只有中间断卷能判，最后一段残缺会解出错的东西 | 截断最后一卷 → 明确提示「最后一卷不完整」 |
| 6 | **zip 里的符号链接**（对齐 tar 那条路） | tar 已能还原链接，zip 装 Linux 软件包时也常见 | 带链接的 zip 解出后链接还原；恶意链接被拒 |
| 7 | **五态审计**：空 / 加载 / 成功 / 失败 / 部分成功，逐页过一遍 | 每种结局界面都有话说，不留白屏和死按钮 | 五个页面 × 五种状态都有实拍证据 |
| 8 | **首屏单一入口收口**（AUDIT-17b #15） | 新手打开先看见一个问题：「我该点哪」 | 首屏只有一个主动作，其余是次要入口 |
| 9 | **默认打开方式**：常见压缩 MIME 位次提到 File Roller 前面 | 双击压缩包直接是我们，不用右键选 | 双击 zip/rar/7z 打开的是杨三海解压 |
| 10 | **托盘 / 后台**：解压中最小化到托盘 | 解大包时可以把窗口关掉，它继续解 | 关窗口任务继续，托盘图标能看到进度 |
| 11 | **断点续传**（要动协议 + 状态持久化） | 解到 90% 断电/取消，下次不用从头来 | 中断后重开能接着解，已验证字节一致 |
