# yshjy 界面规范与文案表（UI-SPEC）

> 版本：v1（2026-10-16）　覆盖：CLI / 桌面 GUI / 手机端
> 解决 `06-工程与设计审查.md` 中的 B1（只设计了成功路径）与 B2（文案缺失）

---

## 一、设计原则（5 条，遇到分歧按这个裁决）

1. **简单好用**——用户拍板的第一原则，宁可少个功能，不要多一步操作。
2. **说人话**——不出现"central directory"这种词；坏消息也要给"下一步怎么办"。
3. **三端同一套逻辑**——手机「+ → 列表 → 单击/长按」；桌面「拖入 → 列表 → 单击/右键」；CLI「命令 → 列表 → 参数」。学会一次，三端通用。
4. **透明优先**——不替用户做隐藏决定：先列出内容、标出有锁、给出选项。
5. **异常不吓人**——坏了要说清"发生了什么 + 为什么 + 你能做什么"，绝不只甩一句"文件损坏"。

### F. 失败原因（按原因分类 —— 这是"说人话"的核心）
| 原因码 | 用户看到的 |
|--------|-----------|
| `NOT_ARCHIVE` | ℹ️ 原因：这个文件既不是压缩包，里面也没藏着压缩包<br>💡 确认一下有没有下错文件？ |
| `NEED_PASSWORD` | ℹ️ 原因：这个包有密码保护<br>💡 看下载页面或同目录的「说明.txt」 |
| `WRONG_PASSWORD` | ℹ️ 原因：密码不对（已试 N 次）<br>💡 注意密码可能含中文、区分大小写 |
| `TRUNCATED` | ℹ️ 原因：文件不完整（少了结尾部分）<br>💡 通常是下载没完成，重新下载试试 |
| `MISSING_VOLUME` | ℹ️ 原因：缺少分卷（需要 xxx.002，但没找到）<br>💡 把所有分卷放在同一个文件夹里再试 |
| `DATA_LOST` | ℹ️ 原因：文件中间有一段数据丢失了<br>💡 重新下载，或用"救援模式"尽量救出剩下的 |
| `ENCRYPTED_UNBREAKABLE` | ℹ️ 原因：这个包加密了，但没有密码解不开<br>💡 找发布者要解压码 |
| `NOT_ENOUGH_SPACE` | ℹ️ 原因：磁盘空间不够<br>💡 换个位置或清理一下空间 |
| `PERMISSION_DENIED` | ℹ️ 原因：没有权限写入这个位置<br>💡 换个文件夹试试 |
| `VIDEO_UNPLAYABLE` | ℹ️ 原因：这个视频本身有问题（可能是作者打包时的 bug）<br>💡 里面的文件还是能解出来 |
| `INTERNAL` | ℹ️ 原因：程序内部出错了<br>💡 点"导出诊断信息"，把它发给我们就能修 |

### G. 警告
```
⚠️ 这个方式生成的文件，有些解压软件可能找不到（建议用 7-Zip 或我们的工具）
⚠️ 解出了可执行文件，这类资源偶尔会被植入恶意程序，运行前建议扫一下毒
⚠️ 这个包的文件名也加密了，需要正确的密码才能看到内容
⚠️ 空间不太够，可能会中途失败
```

## 四、视觉规范

### 4.1 配色（青色系 —— 贴合用户偏好）
```
主色        #2EC5CE  青（Miku 青的柔和版）
主色深      #1A9AA3  按下态
成功        #3DBE6E  绿
警告        #E8A33D  琥珀
错误        #E05A5A  柔红（不用刺眼的正红）
背景（浅）  #F7F9FA
背景（深）  #12181A  深青黑
文字主      #1C2628 / #E8F0F2（深色模式下）
文字次      #6B7A7E
分割线      #E1E8EA / #223033
```
**规则**：状态色**不能只靠颜色区分**（色盲友好）—— 必须同时有图标或文字。

### 4.2 图标策略 ⚠️ 重要决策
| 环境 | 策略 |
|------|------|
| **GUI（桌面+手机）** | **不用 emoji**！改用内置矢量图标（Flutter Material Icons 或自绘）。原因：emoji 跨平台渲染不一致，某些安卓机型/旧版本会显方框 —— 而用户对中文/符号显示要求很高 |
| **CLI** | 可以用 emoji（终端字体支持普遍较好），同时保证**纯文字也能读懂** |
| **报告/文档** | emoji 可用（Markdown 渲染环境可控） |

### 4.3 字体与排版
```
中文     Noto Sans CJK SC / 思源黑体（系统自带优先）
数字与代码 等宽字体（JetBrains Mono / Noto Sans Mono）
字号层级  12 / 14 / 16 / 20 / 24（不再多）
行高      1.5
间距      8 px 网格（8/16/24/32）
圆角      卡片 12 / 按钮 8
```

### 4.4 深色模式
默认跟随系统；青色在深色底上要提亮一档（`#3ED9E3`）。

```
└───────────────────────────────────────────┘
```

### 4b.6 键鼠操作约定（桌面特有）
```
双击列表项      打开所在的文件夹
单击列表项      选中（右侧 ⋯ 出现）
右键            完整菜单（打开/解压/压缩/重命名/删除/详情/打开位置）
Del             删除选中（需确认）
Ctrl+A          全选
Ctrl+V          粘贴路径（自动开始识别）
拖入窗口        自动识别并加入队列
Esc             取消当前操作 / 关闭面板
```
**与手机端的差异**：桌面**双击打开文件夹**（手机是单击打开文件），因为桌面更容易定位到文件位置。

## 五、组件规范

| 组件 | 规范 |
|------|------|
| **文件列表项** | 左：类型图标 + 文件名（过长省略中段）；右：大小 + 状态徽标 + `⋯` 菜单键；高度 64（手机）/ 48（桌面） |

| **进度条** | 必带：百分比 + 字节数 + 预计剩余；不确定时用"不确定态"（来回滑动的条） |

| **对话框** | 标题问句化（「要删掉吗？」），按钮动宾明确（「删除」「保留」） |
| **长按/右键菜单** | 打开 / 解压 / 压缩 / 重命名 / 删除 / 详情 / 打开所在位置 |

## 九、竞品调研结论（✅ 2026-10-16，45 张截图 + 1026 行报告）

> 报告：`refs/analysis/07-竞品界面调研.md`　截图存档：`refs/ui-reference/`（45 张）

### 9.1 战略级发现：这是"界面荒地"
```
三个最直接的对手（Complex-unzip-tool-v2 / TR-Supowe / baidupan-zip-extract）
全部是纯命令行工具，仓库里没有任何界面截图（已全仓确认）

→ 在所有做「解伪装包」这件事的工具里，没有一个把界面做好过
→ **界面是我们的主战场，不是补充项**
```

### 9.2 吸收进设计的 3 个交互

**① 智能解压三条规则**（源自 Bandizip 官方文档）
```
· 包里只有一个条目（单文件或单文件夹）→ 直接解到当前目录
· 否则                                → 自动建同名文件夹
· 重名                                → 自动追加 (2)、(3)
→ 默认开启。伪装包解出来层级最深，这条能避免"解完找不到东西"
```

**② 双菜单**（源自 ZArchiver，已是手机端事实标准）
```
点按  = 内容操作（打开 / 解压）
长按  = 文件管理（重命名 / 删除 / 详情 / 打开位置）
多选时 = 顶部标题位复用为「已选 N 项」
```

**③ 完成提示三段式**（源自 Sunpack，最干净的完成态）
```
第一行：做了什么   解压完成
第二行：结果+耗时  351 个文件成功，用时 2 分钟
第三行：下一步     [打开输出目录]
```

### 9.3 必须避开的 3 个坑（真实事故）

| # | 坑 | 来源 | 我们的对策 |
|---|----|------|-----------|
| 1 | **明文打印密码** 🔴 | Complex-unzip-tool-v2 会打印 `Trying password: 123456` 甚至成功后的密码 | **永远打码**（`1234**` / `●●●●●●`）。终端会被录屏分享，这是真实泄露 |
| 2 | **清屏冲掉日志** | v2 在密码失败菜单里调用清屏，用户以为要重来 | 日志**只追加，绝不清屏**；要刷新就用"重绘当前区域"而不是清历史 |
| 3 | **隐藏双段式菜单** | TR-Supowe：处理"无密码"要按回车再按 1，零提示零默认值 | 每个交互**必须有默认值 + 明确提示**；能用一次确认解决的绝不拆两步 |

### 9.4 界面布局参考（ZArchiver 实测截图）

```
顶部栏    左：返回    中：双行（选中数 / 当前路径）    右：搜索 / 排序 / ⋮
列表项    左：类型图标    中：主标题 + 次要信息（两行）    右：元信息（大小 / 类型）
底部      ZArchiver 没有底栏与悬浮按钮（操作收在顶部与长按菜单）
```
**我们的差异**：我们的场景是"处理文件"而非"浏览文件管理"，所以
**保留 `+` 悬浮按钮**（添加文件的主入口，最直观），同时参考它的列表三段式布局。

## 十、错误码 → 界面形态映射表（Flutter 实现依据）

> ⚠️ 前提（三层审查修正 1）：**引擎只产出错误码 + 结构化参数，外壳负责渲染**。
> 下表是 GUI 侧的实现依据；CLI 侧渲染成文字（见 CLI-SPEC）。
> 图标一栏给的是**语义**（用 Material Icons 名，**不用 emoji** —— 见 4.2 决策）。

| 错误码 | 图标（Material） | 标题 | 正文 | 按钮 |
|--------|-----------------|------|------|------|
| `NEED_PASSWORD` | `lock` | 这个包有密码保护 | 需要 {n} 个密码才能解开 | [输入密码] [试密码本] [跳过] |
| `WRONG_PASSWORD` | `lock_reset` | 密码不对 | 已试 {n} 次 · {建议（中文/大小写提示）} | [再试一次] [看详情] |
| `NOT_ARCHIVE` | `help_outline` | 解不开了 | 这个文件既不是压缩包，里面也没藏着压缩包 | [重试] [看详情] |
| `TRUNCATED` | `trending_down` | 文件不完整 | 少了结尾部分（常见于下载没完成） | [改用救援模式] [重新选择] |
| `MISSING_VOLUME` | `extension_off` | 缺少分卷 | 需要 {缺失的分卷名}，但没找到 | [选择分卷位置] [看详情] |
| `DATA_LOST` | `heart_broken` | 中间有一段数据丢失 | 救援模式能救出约 {n}% | [尽量救出来] [看详情] |
| `ENCRYPTED_UNBREAKABLE` | `enhanced_encryption` | 没有密码解不开 | 这个包加密了，需要发布者提供解压码 | [重试] [看详情] |
| `NOT_ENOUGH_SPACE` | `sd_card_alert` | 空间可能不够 | 需要 {x}，可用 {y}，还差 {z} | [换个位置] [只解压部分] [继续试试] |
| `PERMISSION_DENIED` | `block` | 没有权限写入 | 这个位置不让写 | [换个位置] |
| `VIDEO_UNPLAYABLE` | `movie_filter` | 视频本身有问题 | 可能是打包时的 bug，但里面的文件仍能解出 | [继续解压] |
| `INTERNAL` | `bug_report` | 程序出错了 | 点下面的按钮导出诊断信息，发给我们就能修 | [导出诊断信息] |

**成功 / 部分成功**（非错误，但要设计）
| 结果 | 图标 | 标题 | 正文 | 按钮 |
|------|------|------|------|------|
| `Success` | `check_circle` | 解压完成 | {n} 个文件 · {大小} · 用时 {t} | [打开文件夹] [分享] |
| `Partial` | `warning_amber` | 救出了大部分文件 | 成功 {a}/{b}（{p}%）+ 缺失清单 | [打开文件夹] [看详情] |
