# AI 自测验收方案（2026-10-30 起草）

> ⚠️ **2026-11-01 部分作废（用户当场定的规矩）**
>
> 本文第 3 节「本机能力盘点」和第 5 节「第三层怎么做」里写的 **"由 AI 用 computer-use 开应用、自己点、自己截图"
> 已作废**。现在的规矩是：**截屏和点击一律由用户本人做**，AI 只负责把要点的位置说到像素级
> （"左侧导航最后一项""底部按钮上面那行最右边"），他点完把截图回传。AI 若自己操纵他的窗口，
> 他会立刻质问"谁让你截屏了"。
>
> **仍然有效的部分**：验收四层结构（第 4 节）、门禁规则、用例清单 A1~A7/W1（改由用户亲手点）、
> 诚实规则（没跑写"未验"）、以及第 8 节「明确不做」。
>
> 一句话：**方案的分层和清单照用，"谁来点"换成用户本人。**


> 一句话：**以后发版前，必须有一层「真界面被人亲手点一遍 + 截图」的验收。缺这一层，不发版。**
>
> 这份是唯一一份验收方案，别再另开账本。开工时看这里就够了。

## 1. 为什么会有这份方案（先认账）

2026-10-30 一天之内连出三版（0.9.31 → 0.9.32 → 0.9.34），全是因为**界面层 bug**：

| # | Bug | 谁发现的 | 当时测试状态 |
|---|---|---|---|
| 1 | 加密包在图形界面里**永远没有输密码的地方** | 用户真机点 | `cargo test` 390 绿、`flutter test` 69 绿 |
| 2 | 换输入文件后，**输出名还停在上一个**，文件按旧名生成、用户找不到 | 用户真机点 | 89 绿 |
| 3 | 打包完成后**不显示文件在哪**，也没有"打开文件夹" | 用户真机点 | 89 绿 |
| 4 | 界面算路径**写死 `/`**，Windows 上算错 | 写方案时顺手发现 | 无人发现过 |

**根因不是不仔细，是测试结构缺了一层：**

```
        ▲  真实用户点击          ← 完全空白（4 个 bug 全在这儿）
       ╱ ╲
      ╱   ╲  装机后四项验证       ← 手工验过，但只验"能不能跑"，不验"界面对不对"
     ╱─────╲
    ╱ 界面逻辑 ╲  flutter test 89  ← 假的界面：不启动真窗口、不点真按钮
   ╱───────────╲
  ╱   引擎    ╲  cargo test 390  ← 很厚，但测的是命令行那层
 ╱─────────────╲
```

结论：**测试写得再多，只要没覆盖"用户手指点到的那一层"，就等于没测。**

## 2. 调研结论（2026-10-30 上网核实）

| 方案 | 结论 |
|---|---|
| **Maestro** | ❌ 官方文档明写「Flutter Desktop 还不支持」（`docs.maestro.dev`），别白折腾 |
| **Patrol 4.x** | ⚠️ 跨平台 E2E 好手，但重心在移动端/原生弹窗（权限、通知），桌面不是它的主场 |
| **Flutter 官方 `integration_test`** | ⚠️ 能启动真 app、点真控件，但**碰不到系统文件选择框**（原生 UI）—— 而我们的 bug 恰好都在"选文件"前后 |
| **Computer Use Agent（CUA）** | ✅ 像人一样"看截图 → 点鼠标 → 再看"，天然覆盖整个界面。ML6 的 `cua-uat` 实测：**28 个功能 bug 抓到 27 个**、8 个视觉 bug 抓到 6 个 |

**选 CUA 做第四层。** 理由：不需要改产品代码、不需要用户懂技术、最接近真人的使用路径。

## 3. 本机能力盘点（`computer-use-linux doctor` 实测，2026-10-30）

| 能力 | 状态 | 走什么 |
|---|---|---|
| 截屏 | ✅ | xdg-desktop-portal RemoteDesktop |
| 鼠标点击 | ✅ | 同上（会真移动光标，Wayland 限制） |
| 键盘输入 / 组合键 | ✅ | ydotool + `/dev/uinput`（权限已配好） |
| 窗口列表 / 切窗口 | ✅ | GNOME Shell 扩展 |
| 无障碍树（AT-SPI） | ⚠️ 有，但**对 Flutter 窗口不能用** | 见下面坑 |

（doctor 里报红的 `cosmic / kwin / hyprland / i3 / gnome-screenshot` 都是无关后端，不影响。）

### 已知坑（都是实测踩出来的，别重踩）

1. **对 Flutter 窗口绝对不要调 `get_app_state`（带无障碍树的那个）** ——
   同步等 AT-SPI 回应，实测卡满 300 秒超时，还会把被测应用拖成系统「应用无响应」弹窗，只能杀掉重开。
   → 一律用 `screenshot` + 视觉模型读界面。
2. **首次调用会弹「允许远程交互」**（GNOME 安全机制，一次性，本登录会话内一直有效）。
   这个 MCP 调用是**同步阻塞无超时**的 —— 所以调用前必须先跟用户说一句「马上会弹，请点允许」，
   绝不闷头调，否则双方互等把对话卡死。
3. **三套坐标空间别混用**：
   - 截图裁到窗口内 → 图内坐标 = 窗口左上角原点
   - `click(relative:true, window_id=…)` → 窗口内坐标
   - `scroll` 的 x/y → **屏幕绝对**坐标（没有 relative 选项）
4. **别把「工具返回 ok:true」当成"操作成功"**，要回读截图确认。

## 4. 验收四层（发版门禁）

| 层 | 跑什么 | 覆盖 | 谁跑 | 现状 |
|---|---|---|---|---|
| ① 引擎 | `cargo test` | 打包/解压/加密/分卷/命名真算得对 | 我 | ✅ 390 过 |
| ② 界面逻辑 | `flutter test`（带 `XDG_CONFIG_HOME` 临时目录） | 按钮背后的判断逻辑、错误码文案 | 我 | ✅ 89 过 |
| ③ **真界面** | **computer-use 开应用、真点、截图** | **用户手指点到的那条路** | 我 | ⛔ **从没做过（本次补）** |
| ④ 装机 | `dpkg`/`--version`、菜单 14 格式、`tests/pick.sh`、装机版真打包解压 sha256 | 包装得对不对、装完能不能用 | 我 | ✅ 每版都做 |

**门禁规则：① ② 必须全绿；③ 的用例必须逐条打勾（没跑写"未验"）；④ 装机后必做。**

## 5. 第三层怎么做（固定剧本，共 7 个用例）

> 目标：把"用户会点的每一条路"都亲手指一遍，每条留截图。

| # | 操作 | 期望（断言） | 对应历史 bug |
|---|---|---|---|
| A1 | 打开「杨三海解压」 | 主界面正常、无白屏、无报错 | — |
| A2 | 拖入 AES 加密包 | **预览页直接出现解压码输入框**（不能等失败才给） | bug #1 |
| A3 | 故意输错密码 → 开始解压 | 提示"解压码不对"，且**能修改重试** | bug #1 |
| A4 | 输对密码 → 解压 | 进度走完，报成功，产物落盘（数目对得上） | — |
| A5 | 打包页依次选两个不同文件 | **输出文件名跟着当前输入变**（不是停在上一个） | bug #2 |
| A6 | 点 → 打包完成 | 卡片显示「文件在这儿：<真实路径>」+ 两个按钮 | bug #3 |
| A7 | 点「打开所在文件夹」 | 文件管理器跳到该目录，产物就在里面 | bug #3 |

补充用例（有 Windows 机器时加跑）：
- W1：Windows 上打包，输出默认名应为 `C:\…\原名.新扩展名`，不能算成 `C:\…\原名.zip.zip` 之类 → 对应 bug #4

### 记录格式（贴进 `docs/RELEASE-CHECK.md` 当版小节）

```
### 真界面验收（computer-use）
A1 ✅ 截图 shots/0.9.34-a1.png
A2 ✅ 截图 shots/0.9.34-a2.png   —— 输入框在，标签「解压码（这个包有 5 个文件加密）」
A3 ✅ 截图 shots/0.9.34-a3.png
A4 ✅ 截图 shots/0.9.34-a4.png   —— 5 个文件 sha256 与源一致
A5 ✅ 截图 shots/0.9.34-a5a.png / a5b.png（换文件前后名字确实变了）
A6 ✅ 截图 shots/0.9.34-a6.png
A7 ✅ 截图 shots/0.9.34-a7.png   —— Files 跳到 ~/下载/packtest
W1 未验（本机无 Windows 桌面）
```

### 诚实规则（写进流程，防止再吹）

- 没跑 = 写 **未验**，并写原因。
- 只跑了一半 = 写 **部分**，并写清哪一半。
- **禁止**出现「应该没问题」「按理说可以」这类话；验收表里只允许「✅ 有截图」「❌ 失败」「未验（原因）」。
