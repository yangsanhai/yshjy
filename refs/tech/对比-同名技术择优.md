## 2. 缓冲区大小与重叠策略

| 项目 | 出处（文件:行） | 做法 | 判定 |
|------|----------------|------|------|
| **7-Zip** | `ZipIn.cpp:658-659` | `kCheckSize = 1<<16`（64 KiB，结构校验用）／`kBufSize = 1<<17`（128 KiB，读缓冲）；注释明写 "**kBufSize must be > kCheckSize**" | ★ 缓冲与校验量匹配的第一原则 |
| 7-Zip | `ZipIn.cpp:32` `kSeqBufferSize = 1<<17`；`:1730` `kBufSizeMax = 1<<17`（注释：必须 > `64KiB + kEcdSize + kEcd64Locator + kEcd64_Full`） | 中央目录读取也统一 128 KiB | ★ 把"窗口 ≥ 最大结构"写进注释，防后人调小 |
| 7-Zip | `ZipIn.cpp:1002` `const unsigned kBufSize = 1 << 10;` | 小读（<64 KiB 的头）用 1 KiB，避免大缓冲拖慢小文件 | 精细 |
| **zip2** | `magic_finder.rs:95` `BUFFER_SIZE = 1024`；`:40`、`:75` `magic_overlap = MAGIC_LENGTH - 1 = 3` | **1 KiB + 3 字节重叠** —— 只要能找到 4 字节魔法数即可 | ★ 代价最低；但不做后续结构校验（重叠只需覆盖签名长度） |
| zip2 | `readers.rs:327` `io::BufReader::new(...)` | 解压链用默认 8 KiB `BufReader` | 常规 |
| **unar** | `XADZipParser.m:131` `chunkSize = 0x10000`；`:185` | **64 KiB + 40 字节重叠**（20×2） | 折中；重叠量按"最长的跨块结构"= ZIP64 定位器 20 字节 ×2 算，有推导 |
| **sevenz-rust** | `reader.rs:305` | 尾部扫描窗口 **1 MiB**；`:372` `vec![0; next_header_size]` 按声明大小整块读（非重叠式） | 面向"头可能很长"的 7z，与 ZIP 场景不同 |
| **SteganographierGUI** | `Steganographier.py:2903` | 解压时 `source.read(32*1024*1024)`（**32 MiB** 块） | 只图吞吐，未考虑重载 |
| PeaZip | — | **未找到此类实现** | — |
| **我们（现状）** | `src/layout/zip.rs:105` `DEFAULT_WINDOW = 1 MiB` | 尾部整窗读入再标量倒扫 | 与 7-Zip 的"窗口 ≥ 最大结构"一致 |

**最优判定：无单一赢家，按方向分工 ——**
- **反向找 EOCD**：抄 7-Zip 的"窗口 ≥ `64 KiB + EOCD/ZIP64 结构`、且缓冲必须大于校验量"这条**原则**（`ZipIn.cpp:659/1730` 两处注释），
  我们取 1 MiB 已覆盖，可保留。
- **正向扫描**：抄 zip2 的 `1 KiB + (签名长度-1)`（`magic_finder.rs:95/40`）——重叠的**充分必要量就是签名长度-1**，多给无用。
- **重叠量公式**：`重叠 = max(一次匹配需要向后看到的字节数) - 1`。zip2 只看 4 字节签名 → 3；unar 要看跨块的 20 字节定位器 → 40。这条把两家统一了。

> ⚠️ 与我们的实测结论对齐：**缓冲区小的时候，标量优于 SIMD**（详见 §1 与 §综合结论的 SIMD 备注），
> 所以"把窗口放大换 SIMD"只在窗口到几十 MB 时才成立 —— 别照抄 zip2 的 memchr 到小窗口。

且"描述符后必须是下一个头签名"这条把误报率压到极低 —— 这正是我们能啃下"CD 被改坏"包的根因之一。

我们的场景（CD 不可信）恰恰是 zip2 的盲区 —— 这是选用 zip2 时必须自己补的一块。
我们已对译且放宽了容差，保持。

**SteganographierGUI 是本项反面教材**（整包进内存），也是我们绝不能重蹈的坑。

## 综合结论：每个技术点我们应该怎么做（融合各家优点）

### 判定汇总表

| # | 技术点 | 最优 | 亚军 | 我们的动作 |
|---|--------|------|------|-----------|
| 1 | 找 EOCD | **zip2**（双向 trait + 位置缓存 + 严格窗口下界） | 7-Zip（每候选 64 KiB 结构校验） | 🔄 补"命中缓存 + 结构校验" |
| 2 | 缓冲区与重叠 | **无单一赢家**（方向分工） | — | ✅ 保留 1 MiB 反扫；正向用"1 KiB + 签名长度-1" |
| 3 | 前导垃圾偏移反推 | **zip2**（一行公式 + 三路覆盖 + `Known` 接口） | 7-Zip（等价但分散） | ✅ 已有公式；🔄 补 `ArchiveOffset::Known` |
| 4 | 目录表救援 | **7-Zip**（唯一系统化） | unar（局部续扫） | ✅ 已实现且增强，保持领先 |
| 5 | 数据描述符 | **7-Zip**（两轮校验） | unar（单轮，无 CRC） | ✅ 已对译且放宽容差 |

### 逐点落地建议

1. **找 EOCD**：以 zip2 的 `MagicFinder`(trait 双向) + `MagicPositionCache` 为骨架（`magic_finder.rs:101`、`find_central_directory.rs:24`），
   合入 7-Zip 的"每个候选做 64 KiB 结构校验"（`ZipIn.cpp:733/549`）。
   窗口下界按 zip2 的推导（`find_central_directory.rs:186-189`：`file_len - 22 - 4 - 65536`）。

2. **缓冲区**：分方向定策 —— 反扫取"窗口 ≥ 最大结构（64 KiB+EOCD/ZIP64 系列）"，我们 1 MiB 已够
   （对齐 7-Zip `ZipIn.cpp:659/1730` 两处注释的**原则**，而非硬编码值）；正向扫描重叠量用
   `签名长度 - 1`（zip2 `magic_finder.rs:40`）。跨块结构（如 ZIP64 定位器）另按"最大跨块长度 ×2"
   给重叠（unar `XADZipParser.m:185`）。

3. **偏移反推**：公式保持 `base = cd_at - cd_offset`（= zip2 `find_central_directory.rs:203`，我们 `src/layout/zip.rs:188`），
   **新增** `ArchiveOffset::{Detect, Known}` 式的可缓存/可给定接口（zip2 `config.rs:13`），
   逐层探测时上层可传已知偏移省一次扫描；自校验 `PK\x03\x04` 保留（我们 `verify_base`）。

4. **救援**：保持我们现有 `src/rescue.rs`（已对译 7-Zip LOCALS-CD-MODE + `IsStrangeItem` + `find_descriptor`）。
   建议补 7-Zip 的 `ZIP_SELF_CHECK` 思路（`ZipIn.cpp:62-68`）做**自对拍**：CLI 加隐藏开关，任何包都跑一遍
   LOCALS-CD-MODE 与 CD-MODE 结果对比，用于回归发现偏差。

5. **描述符**：保持 `src/rescue.rs:197` 的条件①②③ + 容差 1。建议再补 7-Zip 的**第二轮** `CheckDescriptor`
   （`ZipIn.cpp:1577`）：抽完文件后独立复核 `crc/packSize/size` 三项全等，作为"数据完整性最后一道闸"。

6. **资源控制**：保留我们的 `ResourceProfile` 三档 + 扫描深度（`src/hardware.rs`，特色是"磁盘优先"）。
   **补** sevenz-rust 的"解压前按字典大小算内存、超限直接拒绝"（`decoder.rs:106-114`），
   把 OOM 变成可读错误；`-mmt` 式表达力（`off/on/N/百分比`）选做。

7. **文件名编码**：实现五级回退链（这是本对比最有价值的融合）：
   `flag(UTF-8) → Info-Zip Unicode Path 扩展(带 CRC 校验归属, 7-Zip ZipItem.cpp:386)
   → 显式代码页(7-Zip ZipHandlerOut.cpp:564) → 探测器+置信度(unar XADString.m:342-403)
   → escaped-ASCII 兜底(unar XADString.m:104-135)`。
   前三级是确定性信息，后两级是兜底；**任何情况下都不因编码猜错而丢文件**。
   注意 zip2 只有 CP437（`cp437.rs:8-25`），编码层必须完全自建。

8. **分卷**：抄 unar 的 `offsetForVolume`（`XADZipParser.m:450`，`for(i<disk) offset += sizes[i]`）
   完成"卷内偏移 → 全局偏移"，与我们的偏移反推体系天然配套；
   卷名识别可对齐 unar 的 `.zNN` / `.zip.001` / `.1.zip` 三类正则（`XADZipParser.m:67/78/88`）。
   大目标才对标 7-Zip 的 `CVols` 虚拟流（`ZipIn.cpp:2484`）。**注意 zip2/sevenz-rust 明确不支持多盘，是已知缺口。**

9. **ZIP64**：以 zip2 的三重校验为骨架（locator↔EOCD64 disk 一致、`record_size+overhead==expected`、
   条目数越界预判 `find_central_directory.rs:229-247/292-302`），补 7-Zip 的第二/第三条退化路径
   （变长 EOCD64 用 locator 绝对偏移 `:1806`；偏移 != 0 试 `MarkerPos + locator 偏移` `:1818`）。
   **不采用** unar 的 `numentries += 65536` 启发式（`:309`）。
   zip2 暴露 `zip64_extensible_data_sector`（`zip_archive.rs:458`）值得照抄（便于诊断）。

10. **流式**：保留我们的 `Window<R>`（`src/io/window.rs`，解决"内嵌数据从 0 开始"）。
    合入 zip2 的两点：① 条目定界用 `Take(compressed_size)`（`types.rs:201-210`）；
    ② **支持无 Seek 的纯 `Read`**（`stream.rs:247`）以便管道式处理。
    警惕 SteganographierGUI 的反面做法（整包进内存，`Steganographier.py:3069/3087`）。

### ⚠️ 关于 SIMD 的适用条件（重要，别再踩）

我们已有实测结论（`src/layout/zip.rs:89-94` 的注释就是这条结论的落地）：

```
同一 8.7 GB 文件、1 MiB 窗口：
  标量  rposition/windows  → 41 µs    ← 采用
  memchr::rfind (SIMD)     → 610 µs   ← 慢 15 倍
结论：窗口小时标量更快（SIMD 的建表/调用开销盖过收益）；
      只有把窗口放大到几十 MB 时才值得换 SIMD。不要盲抄参考项目。
```

因此本对比中所有"zip2 用了 memchr"的条目（`magic_finder.rs:4` 引 `memchr::memmem::{Finder, FinderRev}`）
**结论必须附加条件**：

- ✅ **适用**：窗口 ≥ 数十 MB 的全文件扫描、单次搜索区间远大于 SIMD 建表开销时 —— 值得上 SIMD。
- ❌ **不适用**：我们当前 1 MiB 级尾部窗口反扫 —— 标量更快，**保持标量**（已回滚 memchr）。
- 🔀 **中间态建议**：把"是否用 SIMD"做成**按窗口大小分支**（`window >= 阈值` 走 memchr、否则走标量），
  而不是全局二选一。这样两家的长处都能用上，也和我们 §2 的"窗口按方向/结构定大小"一致。

> 这条同时修正了"照抄 zip2 的实现"这一直觉 —— zip2 的 `MagicFinder` **架构**（双向 trait + 缓存 + Take 定界）
> 值得抄，但它的 **SIMD 内核**在我们的小窗口场景是负优化。**抄架构，不抄常数。**
