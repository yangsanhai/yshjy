## 1. 路径穿越（Zip Slip / `../` 逃逸）

这是所有安全点的地基，六家差异最大。

| **zip2** (Rust) | `src/path.rs:57-85`（`enclosed_name`，`depth.checked_sub(1)?` 下溢即拒）、`:22-45`（`simplified_components`，供 root-dir 简化用，注释明说**不可**用于包含性判定）、`:178-276`（`resolve_enclosed`，逐组件解析、`..` 在 `base` 处即拒、末尾 `starts_with(base)` 复核）；`src/read/zipfile.rs:270-318`（`safe_prepare_path` 落地到解压循环 `:459`） | 两条路径：`enclosed_name` 做**纯字符串级拒绝**（下溢/越界即 `None`）；`resolve_enclosed` 做**逐组件真实解析**，遇到符号链接把目标组件**重新入队**再逐段检查 | ⭐ **次优且更工程化**。比 7zip 多一层"组件内含分隔符即拒"（防 verbatim 路径 `\\?\C:\..\b` 被拆错），`:71-77` 有测试 |

- 我方现状：`src/safety.rs:130-169` 的逐段 `match`（`Normal` 白名单 / `ParentDir` 直接拒 / `Prefix`+`RootDir` 直接拒）**已经是正确且严格的一档**，`..` 一律拒比 7zip 的计数法更保守（宁可误杀不放过），无需改成计数法。**缺口是"组件内含分隔符"这一条**（见 §1 缺口）。

## 5. 解压炸弹（压缩比、嵌套层数、总字节上限）

**先给一个残酷事实**：六家里**没有任何一家**实现了"压缩比上限"（ratio limit）。这条是我方**独有**。

| 项目 | 出处(文件:行) | 做法 | 判定 |

# 【综合结论】我方应怎么做

## A. 逐安全点的落地方案

### A1. 路径穿越 —— **维持现状 + 补一条"组件内分隔符"**
- **不改成 7zip 的计数法**。我们 `src/safety.rs:130-169` 的"`..` 一律拒"比 7zip 的分级计数更保守，符合我们"宁可误杀"的定位（用户丢进来的是可疑伪装包，不是正常包）。
- **抄 zip2 `src/path.rs:71-77` 那一条**：某个 `Normal` 组件里若仍含 `/` 或 `\`，直接拒（防 `\\?\C:\..\b` 被解析成一个组件后在拼接时又被拆开）。我们已做 `\`→`/` 归一（`:103`），但归一发生在**分段之前**，所以这条对我们是补强而非必需 —— 仍建议加，作为"归一后二次确认"。

### A2. 绝对路径与盘符 —— **维持拒绝策略，补 verbatim 归一（Windows 专属）**
- 我们的做法（`:` 一律拒 + `is_absolute()` 拒 + `Prefix` 拒）方向正确且比 PeaZip 的"`:`换`_`"更好（不静默改文件名）。
- **抄 zip2 `src/path.rs:118-154`**：Windows 下把 `\\?\C:\`、`\\?\UNC\s\sh` 归一到普通形式再和 canonicalize 后的 `base` 比。**但优先级低** —— 只有当我们开始做 `canonicalize` + 写盘才用得上。

### A3. 保留名 / 非法字节 —— **补六个字符**
- 我们已有：保留名（`CON`/`con.txt` 都对）、尾随空格点、控制字符、冒号。
- **补**：`*` `?` `<` `>` `"` `|`（7zip `ExtractingFilePath.cpp:31`、PeaZip `list_utils.pas:1817-1821`、XAD `XADPlatformWindows.m:223` 三家一致）。理由：这些字符在 Windows 上非法，而我们的输入**明确来自 Windows 造的包**，留着会让"解出差一个都打不开的目录"。
- 复用 `resolve_safe` 里已有的逐段循环（`:131-162`），加一个 `is_forbidden_char` 判定即可。

### A4. 符号链接与硬链接 —— **补从零到一（最大缺口）**
- 抄 **zip2 的六档策略**（`src/read/extract.rs:19-39`），但**默认值改成 `NoExtract`**（把链接当普通文件提取或跳过），而非 zip2 的 `ExtractRecursiveInFolder`。理由：我们面向"可疑包"，默认不创建任何链接最安全。
- 必抄的硬约束：
  - 链接目标长度上限（zip2 `extract.rs:17` `MAX_SYMLINK_TARGET_LEN = 4096`）；
  - 跳数上限（zip2 `path.rs:161-163` `MAX_SYMLINK_HOPS = 40`）；
  - 绝对目标必须能归约到 `base`（zip2 `path.rs:95-154`）；
  - **link-over-link 层级上限**（7zip `ArchiveExtractCallback.cpp:2202` `k_DangLevel_MAX_for_Link_over_Link = 9`）—— 如果将来开 `ExtractInFolder`，这条是必需的。
- 硬链接：抄 7zip `ArchiveExtractCallback.cpp:2404` 的思路 —— 硬链接目标同样要走链接安全校验，不能因为"是硬链接"就跳过。

### A5. 解压炸弹 —— **我们已领先，补两块**
- 我们独有 `max_ratio`（`src/safety.rs:203-210`），六家无一实现 —— 保留并保持默认 100。
- **修正一个 bug**：`src/safety.rs:96` 是**硬编码 `512`**，而不是读 `self.limits.max_path_len`（`Limits` 里明明有这个字段，`:24`）。同理 `:196`/`:203` 正确用了 `limits.*`。请把 `:96` 改为 `entry.len() > self…` 不可行（`resolve_safe` 是自由函数、不接 `Limits`）→ 应给 `resolve_safe` 增加一个 `max_path_len` 参数或增加 `resolve_safe_with(root, entry, &Limits)` 变体，让配置真正生效。
- **抄 sevenz-rust 的"防头部说谎"**（§5/§10）：接入各格式解码器时，凡"头部声明的大小/数量"都必须先被"实际可读字节数"钳住（`src/reader.rs:1149-1156` 的 `bounded_count` 就是这个模式）。
- **补嵌套层数**：借鉴 unar `unar.m:107-110` 的开关**但设默认上限**（例如 3 层），而非"默认无限 + 可关"。

### A6. 覆盖与权限 —— **补三项**
1. **覆盖策略枚举**（抄 PeaZip `peach.pas:51600-51604` / unar `unar.m:60-79`），四档：`Skip` / `Rename` / `Overwrite` / `Ask`。**默认 `Rename`**（抄隐写者 `Steganographier.py:1733-1749` 的 `name (1).ext`，并抄它 `_reserved_hide_outputs` 的同批占位防撞名思路）。
2. **权限还原**（抄 zip2 `extract.rs:540-543` + `:547-551`）：Unix 还原 `unix_mode()`，且**子先父后**设置目录权限，配合"解压期间目录保持 `0o700 | mode`"（zip2 `:59-74`）。这个组合直接防掉"父目录只读 → 子文件写不进"的经典 bug。
3. **默认掩码**：新目录用 `0o700` 起步（zip2 `:69`），解完再按归档模式收紧 —— 这同时是 §9 损害限制的基础。

### A7. 文件名编码攻击 —— **补两层（当前完全空白）**
1. **编码回退链**（抄 zip2 `src/types.rs:122-131` + `src/cp437.rs` 的"UTF-8 → CP437"模式，但扩展为 **UTF-8 → GBK/GB18030 → Big5 → SJIS → CP437**，因为我们的用户是中文环境）。XADMaster 的 `XADStringSource` + `UniversalDetector`（`XADString.m:81-93`）是更高级的自动探测，可作为二期。
2. **控制符/双向控制符清洗**（抄隐写者 `Steganographier.py:551` 的**按 Unicode 类别**，这是六家里唯一做对的）：剔除 `Cc`/`Cf` 类（含 U+202E RLO、U+200B ZWSP）。注意 7zip 只在 alt-stream 里替换 RLO（`ExtractingFilePath.cpp:110`）、主路径那句被注释掉了（`:33`），XADMaster 的字符集根本不含 0x202E（`XADPlatformWindows.m:219-223`）—— **这两家都不是可以照抄的对象**。
   - **实现建议**：**转义而非删除**（XADMaster `XADString.m:104-110` 的 `escapedASCIIString` 思路），避免"解出名字和原包对不上"。
3. **超长名**：现有 `max_path_len` 之外，再加**单段长度上限**（隐写者用 255，`Steganographier.py:579-581`）—— 大多数文件系统单段上限就是 255 字节。

### A8. 内存安全设计 —— **维持流式，接入解码器时补"防御性分配"**
- 我们 `src/io/segment.rs`/`window.rs` 的偏移窗口已是流式，方向对。
- **接入任何解码器时立的规矩**（抄 sevenz-rust `src/reader.rs:20-23` + `:390-405`）：
  - 所有"按头部声明大小预分配"的地方，先 `min(声明, 上限)`；
  - 优先惰性增长（`read_to_end`）而非 `vec![0; declared]`；
  - 定一个 `MAX_PREALLOC_BYTES` 常量（7zip 在 LZMA 路径上的等价物是 `SetMemLimit` + 字典大小反推，见 `Lzma2Decoder.cpp:112-125`）。

### A9. 可中断与回滚 —— **中断已有，补回滚**
- `src/io/interrupt.rs` 已达标，保留。
- **抄 XADMaster `XADUnarchiver.m:407-425`**：单文件写入失败/被取消 → **立即删除该半成品文件**。这是六家里唯一正确的做法。
- 可叠加 PeaZip `unitgwrap.pas:1118-1125` 的 `.tmp` 模式（写 `.tmp` 后改名）用于"要么完整要么不存在"的场景，但注意代价：`os.rename` 在跨文件系统时会失败，需要判断同设备。
- 目录层面：抄 zip2 的"非原子但把残缺目录留在 `0o700`"（`extract.rs:322-327` + `:59-74`）作为兜底。

### A10. 资源耗尽防护 —— **补三个上限（`Limits` 扩字段）**
`Limits`（`src/safety.rs:18-27`）当前 4 个字段，建议扩到：

| 新增字段 | 默认值 | 依据 |
|---|---|---|
| `max_entries: u64` | 例：100_000 | 无一家有显式上限；sevenz-rust 的 `bounded_count` 是"相对上限"，我们需要**绝对上限**（我们是桌面工具，用户不该解出千万个文件） |
| `max_nesting_depth: u32` | 3 | unar `unar.m:107-110` 只给了开关，默认无限 —— 我们要给默认值 |
| `max_link_hops: u32` | 40 | zip2 `src/path.rs:161-163`（对齐 Linux `MAXSYMLINKS`） |

另建议把 `MAX_PREALLOC_BYTES` 也放进 `Limits`（默认 `4 << 20`，抄 sevenz-rust `src/reader.rs:23`），因为"单文件预分配上限"和"总解压上限"是两件事。
