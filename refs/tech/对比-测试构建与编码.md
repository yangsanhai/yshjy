### 1.2 我们还能补什么（缺口清单）

1. **fuzz target（第一优先）** —— 目前零模糊测试。复刻 zip2 的读端模型：对不可信字节流跑 `scan → layout → rescue` 全链，上限 16MiB，sink 掉解压结果。写端可用 `arbitrary` 建模「伪装布局」生成（见 1.1.3）。建议用 **cargo-fuzz**（libFuzzer，比 AFL 省事）或 cargo-afl 二选一。
2. **变异测试（mutational）** —— 现有 59 个样本是**手工设计**的；应对 `C1_plain.zip / E2 / E3` 等基准样本做**程序化字节/字段变异**（改 EOCD 偏移、截断 1 字节、翻转 flag bit、改 name_len），批量生成并断言「不 panic、错误码稳定」，补上"没预想到的坏法"。
3. **Miri / 大端回归** —— 我方 `src` 有大量手写字节解析（`layout/zip.rs`、`scan.rs`、`io/window.rs`），Miri + s390x 大端回归价值高（对标 1.1.6 / 1.1.12）。
4. **基准回归（benches）** —— zip2 有 4 个 bench（`Cargo.toml` [[bench]]：read_entry/read_metadata/read_many_entries/merge_archive）。我方 `scan.rs` 的性能是核心卖点（387→160 秒的自研扫描），应固化成 bench 防退化。
5. **feature 开关 × 组合测试** —— 一旦引入 GBK/7z/RAR（见第二节），必须测「关掉某后端仍能编能过」（1.1.7 / 1.1.15）。
6. **端到端真机验收** —— 对标 1.1.16：造出的伪装包必须能被**系统 7z/unzip/ffprobe** 打开，而不是只有我们自己读得懂。
7. **样本来源与许可登记** —— 学 zip2 `tests/data/README.md` 逐样本记来源；我方 A 组源自 SteganographierGUI（GPL 系），需单独标注许可边界。
8. **CI 全缺** —— 无 GitHub Actions；至少要有 fmt + clippy `-D warnings` + `cargo test` + `cargo deny check`（`deny.toml` 已写好但没接 CI）。

### 2.2 编码缺口与落地顺序（可执行）

1. **`:385-421` 的 `decode_name` 重写**为回退链：`flag(0x800)` → **Info-ZIP Unicode Path(0x7075, 验 CRC)** → `flag` 缺失时试 UTF-8 严格 → **GBK/GB18030** → **Big5** → **Shift-JIS** → 兜底 `%xx` 转义（**禁止 `from_utf8_lossy` 这种丢信息做法**）。
2. **GBK/Big5/SJIS 解码表**：用 `feature` 开关按需编译（默认全开中文系，西文可关），目标把增量压在几十 KB 内；表可选「在 `scan.rs` 里做双字节合法性快速预判 + 只在疑似中文时才查表」。
3. **暴露 `codepage: Option<u32>` 引擎参数**（对标 PeaZip `-mcu`），UI 提供"强制 UTF-8 / 强制本地 / 指定代码页"三档。
4. **密码多编码重试**：ZIP 侧按 `GBK → UTF-8 → UTF-16LE` 顺序试，全部失败给明确错误码；7z 侧固定 UTF-16LE。**任何一步都不许 `errors='ignore'`**（2.1.11 教训）。
5. **本地化骨架**：按 7-Zip 的「UTF-8 单文件 + id→offset」或 PeaZip 的「`txt_<ver>_<key>: 值`」建一层，先建 `zh-CN` + `en`。

## 附：本次拆解的三条最高优先结论

1. **测试**：我方唯一真正缺的基础设施是 **fuzz target**（照 zip2 `fuzz/read` 的"整包解压 + 流式二次读"模型，上限 16MiB）与**对现有样本的程序化变异**；59 个手工样本是资产，但覆盖不了"没预想到的坏法"。
2. **编码**：`src/layout/zip.rs:408-421` 的 `decode_name` 现在**用 `from_utf8_lossy` 顶替**，等于"中文名必乱码 + 信息丢失"——这是用户最在意的场景的直接 bug。按 7-Zip `ZipItem.cpp:405-461` 的**四级回退链**重写（flag → Info-ZIP 0x7075 extra field → 用户强制 codepage → 编码猜测链 GBK/Big5/SJIS → `%xx` 可逆转义），是**投入产出比最高的一件事**。
3. **构建**：守住"单一二进制 + 小体积"的关键不是求快，而是**一切新能力都做成 cargo feature 并按需关闭**（zip2/sevenz-rust 的做法），加上 `lto/strip/panic=abort`；同时 `deny.toml` 已写好，**只差接进 CI**。
