## 0. 结论先行（TL;DR）

1. **「伪装包解压」这个赛道目前几乎是界面荒地。** 三个最直接的竞品（Complex-unzip-tool-v2 / Complex-Unzip-Tool / baidupan-zip-extract）**全部没有 GUI，只有终端输出，README 里一张界面截图都没有**。它们的「界面」是一屏滚动的彩色日志。这意味着**界面设计是我们的主要差异化战场，不是补充项**。
2. **真正值得抄的交互全部来自「传统压缩软件」而非「伪装包工具」**：Bandizip 的「智能解压」（自动决定是否建文件夹）、ZArchiver 的「点击→上下文菜单」信息架构、Sunpack 的「完成通知 + 打开输出目录」。
3. **竞品在"用户能不能看懂发生了什么"这件事上集体失分**：明文 `print` 密码、`console.clear()` 冲掉日志、把失败文件默默丢进 `_failed_archives/`、只报「失败」不报「为什么失败、下一步怎么办」。
4. 我们的手机端应该做成 **「ZArchiver 的文件列表 + Bandizip 的智能解压 + 隐写者的拖放/一体化」三者的合体**，而不是复刻任何一个 CLI 工具。

### 1.2 流程分析

`选路径（拖到 exe / argv）→ Step1 建 unzipped/ → Step2 加载密码本 → Step3 扫描 →
Step4 解伪装重命名 → 分组 → 逐组解压（试密码）→ 解压失败则弹 1/2/3 菜单 →
嵌套递归 → 汇总表 → 原包移入回收站`

- 入口只有一个：**把文件拖到 exe 上**，或者 `complex-unzip-tool-v2.exe "D:\path"`。
  没有「双击打开」的空窗口引导，双击 .exe 打开的是命令行帮助。
- 进度表达：两层 Rich `Progress`（总档案数 + 当前组），外加一个文件搬运进度条，靠 `set_active_progress` 互斥切换。
- 报错表达：`✗ / ⚠ / ❌` 前缀 + 颜色（red/yellow），最后统一列在汇总表下方的 `Errors encountered` 列表里。
- 结束表达：满屏 `=` 的绿色横幅 + 无边框汇总表。

### 1.3 可学习点

| 值得学 | 出处 |
|---|---|
| **双语同屏**：每条关键提示都「中文 + 英文」并排，`print_success`/`print_info`/`print_warning`/`print_error` 统一定义了 4 种语义前缀与颜色（✓ 绿 / • 蓝 / ⚠ 黄 / ✗ 红）。这个语义色板可以直接搬到我们 App 的 SnackBar/Banner 体系。 | `rich_utils.py` |
| **结果汇总做成「指标 + 值 + 说明」三列表**：用时 / 档案处理（成功·失败·跳过）/ 文件数 / 错误数 / 输出位置。一次说清全部结果，而不是一句「完成」。 | `print_final_completion` |
| **失败原因给「可能原因清单」**：`Corrupted archives 档案损坏 / Missing passwords 缺少密码 / Incomplete multipart archives 多部分档案不完整 / Unsupported archive format 不支持的档案格式`。这是把「报错」翻译成「用户能自查的假设」，非常值得抄。 | `print_remaining_groups_warning` |
| **改名可回滚**：解压失败会自动 revert 重命名，并提示 `Reverted N rename(s) 已回滚 N 个改名`。失败不留副作用。 | `main._reconcile_rename_history` |
| **失败不删原件**：`当密码错误或分卷缺失时，原文件绝不会被删除`，且只把成功的原包移入回收站。 | README + `_should_delete_original_archives` |

### 1.4 吐槽点（反面教材）

1. **明文打印密码**：`🔐 Trying password 尝试密码: 123456` / `✅ 密码成功: cangku.moe`。
   终端有滚动缓冲、可能被录屏/截图分享，这是**真实的信息泄露**。我们在 App 里必须默认打码，
   只在「查看详情」里点按后才显示，并且不进日志。
2. **`console.clear()` 冲掉日志**：密码失败菜单一弹，用户看到的先前全部进度瞬间消失。
   用户第一反应是「我是不是要重新来」。**永远不要清空用户的历史。**
3. **拖拽是唯一入口，但没有空状态**：双击 exe 得到的是英文帮助文本，普通资源党会懵。
   反观 Bandizip/隐写者都有可见的入口。
4. **失败文件被静默隔离**：TR-Supowe 版把失败包丢进 `_failed_archives`，v2 版只列在日志尾巴里。
   用户在文件管理器里找不到「那批没解出来的东西」——**失败产物必须有明确落点和二次入口**。
5. **没有「上次用的是哪个密码」的可视化**：密码本存在 `passwords.txt` 纯文本里，
   破解出的密码「自动追加」但用户不知道现在库里有什么、哪个包用了哪个密码。
6. **`(y/N) [default: N]` 反直觉**：已经把「回滚改名」这条重要提示打出来了，默认却是「不」。

## 2. TR-Supowe/Complex-Unzip-Tool（v2 的源头）

**截图清单：无。** 源码为单文件 `complex-unzip-tool.py`；README 明确写「程序会自动弹出一个控制台窗口」。

### 2.1 界面布局

纯 `print` 的线性控制台输出，前缀风格是 `[INFO]` / `[ERROR]`：

```
[INFO] 未发现密码库目录，正在创建 'passwords' 文件夹...
[INFO] 正在创建初始密码本: 0_temp.txt
[INFO] 成功从 '1_all.txt' 加载 12 个密码。
[ERROR] 读取密码文件 '0_temp.txt' 时出错: ...
```

### 2.2 流程分析（它的交互设计是本报告里最糟的一段）

README 原文描述了密码环节的操作步骤：

> 执行后会提示输入密码，如果要使用单密码解压接下来的所有文件，则直接输入密码。
> **如果文件无密码，则按下回车后，再按下 1 选择无密码解压。**
> **如果想要使用密码本中的多个密码解压，则在按下回车后再按下 2 选择使用密码本解压，
> 然后再根据输出的密码本列表按下对应的数字编号即可。**

即：**要处理「无密码」这种最常见的情况，用户必须先按一次回车、再按一次 1**。

### 2.3 可学习点

- **密码本分级**：`0_temp.txt`（临时，程序不改）/ `1_all.txt`（主库，自动追加有效密码）/
  用户自建 `my_pass.txt`。用「文件名前缀数字」做排序与优先级，简单但有效。
  → 我们的手机端可以对应「临时密码（本次会话）/ 我的密码本 / 从文件名自动提取的密码」三档。
- **右键菜单集成**（`install.bat` 写注册表），让工具「像压缩软件一样」融入系统。
- 失败文件隔离到 `_failed_archives` 并继续处理，**不中断整个批次**——这个「批次容错」的思路对。

### 2.4 吐槽点

1. **【最严重】隐藏的双段式菜单**：`回车 → 再按 1/2 → 再按编号`。没有默认值、没有提示行、
   没有「直接回车=无密码」的快捷路径。这正是「不会用 WinRAR 的人」会直接卡死的地方。
2. `[ERROR]` 里直接抛 Python 异常字符串（`{e}`），普通用户看不懂。
3. 中英混杂无规范：日志主体中文，但错误码、参数、提示混排。
4. 密码库是明文 txt，且程序会自动往里写，**用户不知道自己贡献了什么进去**。

### 3.2 关键流程：「智能解压」到底在智能什么

Bandizip 官方帮助给出**三条明确规则**（逐字）：

1. 当压缩文件里**只有一个文件**时 → 解压到「当前文件夹」
2. 当压缩文件里的**文件都在同一个文件夹**时 → 解压到「当前文件夹」
   （例：包内有 `photo/` → 就在当前文件夹生成 `photo/`）
3. **若非如此** → 解压到「文件名文件夹」
   （例：`photo-1.zip` 里是一堆散文件 → 新建 `photo-1/` 装进去）
   同名文件夹已存在 → `photo-1 (2)`、`photo-1 (3)`……

官方给出的理由（逐字）：
> 在 Unix 压缩的文件一般都会捆绑在一个文件夹中。将这些文件解压到"文件名文件夹"时，
> 会出现多个同名文件夹，很不方便。此时，使用"智能解压至此"功能就会很方便。

**这就是「解压后目录结构不炸」这个痛点的标准答案。** 对我们的价值：
伪装包/分卷包/套娃包解出来的目录层级最深，用户最容易看到「一坨散文件」或
「深层同名嵌套」，智能解压 + 「压平无意义单子目录」必须默认开启。

### 3.3 可学习点

1. **把「智能」做成默认选项而不是高级开关**：它就在右键菜单第一层，且被高亮演示。
2. **解压路径对话框的 3 个复选框**是一份极好的默认值设计：
   `解压到以压缩包名命名的子文件夹`（默认勾选）/ `解压后删除原压缩包`（默认不勾）/
   `记住设置`。我们手机端可以做成「高级设置」里的同名三开关。
3. **进度窗口同时给「当前文件名 + 已用/剩余时间」**，用户知道卡在哪。
4. **`Extract to sample\` 这一项直接显示将要创建的文件夹名**，不用猜。
5. **完成态用一句话说清**：`Extraction completed successfully.` 而不是只把进度条拉到 100%。

### 3.4 吐槽点

1. **右键菜单里 4 个解压项的图标完全一样**（都是同一个蓝色闪电），只有文字差别，
   `Extract Here` 和 `Extract Here (Smart)` 相差一个括号词，新手根本分不清。
2. **无文字图标按钮**：进度窗口底部一排按钮没有 tooltip 文字，猜谜。
3. **不显示解压速度**。
4. 帮助文档是图文分步（`①→②→③`），但**正文里说"以下图所示"，图却是英文版界面**，
   中文站用英文截图，本地化不彻底。

**列表项布局（逐字核实）**：左侧图标 → 中间**文件名**、文件名**下方**小字显示**修改日期** →
右侧显示 `<DIR>` 或**大小**。深色主题，文件夹图标是橙色，且可带「内容类型小角标」（闹钟/机器人/相机）。

**FAB**：右下角青蓝色圆形按钮，普通态是 `+`，在「粘贴模式」下变成粘贴按钮。
官方说明：`FAB 的动作会随当前目录和列表状态变化`，可在设置里关闭。
在 Grid 显示模式下**点图标不会进入多选**（官方明确的坑）。

**点按压缩包 → 底部上下文菜单**（逐字，顺序即原文）：

```
putty-0.75.tar.gz
👁 View                                    ↗
⬆ Extract here                             解压到当前目录
⬆ Extract to ./<Archive name>/             解压到同名文件夹
⬆ Extract...                               解压到...
──────────────────────────────────
☑ Test                                     测试压缩包
⬇ Compress...                              压缩
```

**长按 = 另一套菜单**：官方原文 `Long press any file or folder name in the file list
to open the additional context menu, which offers you an ability to copy, move, remove,
rename and other applicable operations.`
即 **点按 = 内容操作（查看/解压），长按 = 文件管理（复制/移动/删除/重命名）**。

**多选**：4 种方式（点图标 / 溢出菜单 `Multi-select` / 长按 `..` 全选取消 / 点首项后长按末项）。
多选态下**标题位显示已选数量**，工具栏切换为多选工具栏。**操作按钮全在顶部，没有底部操作栏**
（截图确认：底部只有 Android 系统导航键）。

**粘贴模式**：点复制/剪切/解压后主窗口切到粘贴模式——工具栏变化、FAB 变成粘贴按钮、
不能再选文件、左侧出现 × 取消。点 FAB 开始执行，立刻弹出**进度窗口（带 `Hide` 按钮）**，
显示进度指示 + 当前文件 + 操作描述。

**压缩对话框**：`Archive:` 输入框（`archive.7z` + `...` 浏览按钮）/
`Archive format:` 下拉（7z）/ `Compression level:` 下拉（Normal）/ `Encryption:` 下拉（Data (AES-256)）/
`Password:` 输入框（占位 `Enter password`，右侧**眼睛图标**切换明文）/
`Split into volumes:` 下拉（No）/ 两个复选框 `Delete source files after compression`、
`Create separate archive` / 底部 `CANCEL` `OK`。

**搜索**：`Search` 输入框 + 一排彩色**类型 chips**：`[📁无文字] [APK] [Archive] [Audio] [Document] [Video…]`。
官方提示可用 `*` 通配（`*.zip` 找全部 zip）。**可以不输关键词，只点 chips 列某一类。**

### 4.2 流程分析

`列表浏览 → 点按文件/压缩包 → 底部菜单选动作 → （如需）设置对话框 → FAB 确认 →
进度窗口（可 Hide）→ 回列表`

- 中间态：进度窗口是**独立浮层**，可 `Hide` 收起后继续浏览（后台继续跑）。
- 报错态：官方明说 `You will notice that the toolbar has changed and FAB has transformed…`，
  用**工具栏形变**而不是弹窗来暗示模式切换——这是很好的一致性设计。
- 危险操作：官方有醒目警告 `Be careful with Delete action. Files and folders are deleted
  permanently. There is no Trash folder in the ZArchiver.` —— **它自己承认没有回收站**，
  这是它的重大缺陷，也正好是我们的机会。

### 4.3 可学习点

1. **「点按 vs 长按」双菜单**：主操作（解压）点按即达，文件管理收长按。
   我们的 App 可以**完全照搬这个分工**，并把「一键解伪装解压」放在点按菜单的第一项。
2. **标题位复用为「已选数量」**：多选态不需要额外空间，零成本表达状态。
3. **顶部工具栏随模式形变**（普通/多选/粘贴），FAB 语义跟随。
   → 我们的 App 在「批量解压中」应该让顶部栏变成进度条。
4. **类型 chips 筛选**：不用打字就能筛，对中文用户/大目录极其友好。
5. **密码框带眼睛图标**：明文/密文切换是标配，必须做。
6. **进度窗口带 `Hide`**：允许「后台继续跑 + 回列表看别的」，比模态对话框好。
7. **深色主题为默认**：资源党的使用场景（夜间、看番剧）确实需要。

### 4.4 吐槽点

1. **没有回收站**（官方自认），删除=永久删除。我们对解压出来的原包必须默认进回收站/软删除。
2. **底部上下文菜单里 `Extract here` / `Extract to ./<name>/` / `Extract...` 三项图标完全一样**，
   连 Bandizip 那种括号区分都没有，纯靠读文字。
3. **没有「智能解压」**：解压结构完全靠用户自己选 `Extract here` 还是 `Extract to ./name/`——
   恰好是 Bandizip 用一条规则解决的问题。
4. **FAB 语义不固定**：`+`（新建）/ 粘贴 / 其他，同一位置三种含义，官方文档都要专门解释一段。
5. **没有底部操作栏**：多选后要执行操作得回顶部工具栏，单手大屏够不到。
6. 官方文档只有英/俄，中文用户靠社区教程（Play 商店中文页是机器腔）。

4. **辅助工具是独立小窗**（哈希修改器、验证码生成器），而不是主界面内嵌面板，

5. **日志区字体过小**（约 10-11pt）且无等宽字体，中文日志可读性差。
6. `07-GUI操作演示动画.gif` 是唯一讲清流程的载体，README 没有分步静态图。

## 6. ccloli/baidupan-zip-extract（专治百度网盘 >4GB 损坏 ZIP）

**截图清单：无。** 纯 Node.js CLI，README 只有命令行参数表。

### 6.1 界面布局

```
baidupan-zip-extract [options]
bdzip-extract [options]

Options:
  -f, -i, --file, --input <path>      Specify input zip file (required)
  -o, --output <path>                 Specify path to decompress (default: ./)
  -e, --encoding <charset>            Specify encoding of zip file (default: gbk)
  -l, --logLevel <level>              Specify log level (0-2) (default: 1)
  -h, --help                          Show help page
  -v, --version                       Output the version number
```

- **无进度条**、无交互提示，只有一个 `logLevel 0-2` 决定输出多少。
- `--encoding` 默认 `gbk`——**承认了中文压缩包的编码问题**，这点值得学（我们也要自动识别
  UTF-8/GBK/Big5）。

### 6.2 流程分析

`-f 指定损坏 zip → 工具修正偏移量和大小 → 解到 -o 目录`。
原理是逐文件 seek 偏移，若该位置不存在则 `+2^32`(4GB) 再试，直到找到正确偏移。

### 6.3 可学习点

1. **命令行参数设计的「安静模式」**：`-l 0` 可以完全静音，便于脚本调用——
   我们的 CLI 也应该有 `--quiet` / `--json` 输出模式。
2. **默认编码 = gbk**：对中文用户非常体贴的默认值。

### 6.4 吐槽点

1. **完全没有进度反馈**：>4GB 的包要跑很久，用户不知道死没死。
2. **错误信息只有 logLevel，没有「下一步怎么办」**。
3. ASCII-only 帮助文本 + 全英文，中文用户直接劝退。

   没有「跟随系统语言」的自动选择**。

### 8.2 可学习点

1. **工具栏动词极简且全中文**：`添加/提取/测试/复制/移动/删除/信息`——7 个词覆盖全部操作，

### 9.1 Sunpack（Qinjingxue/Sunpack，GitHub，MIT）

   ZSTD单流 / ZSTD载体 / 三层嵌套载体 / 套装加密分卷.7z.001-003 /
   7Z数据加密 / 7Z头加密 / 7Z伪装 / 7Z跨块载体_01.7z / BZIP2载体_01.bzip2 / GZIP伪装 / …`
   （共 63 项一套 + watch 目录 50 项一套）
2. **★ 完成通知的设计（最值得抄的一条）★**
   ```
   SunPack
   解压完成
   48 个压缩包成功，用时 4 秒
   ```

   一条 Windows Toast：**标题说结果、副标题给量化数字、一个主按钮直达产物**。

3. **watch 模式 = 下载目录自动解压**（放进目录就自动处理，不处理非压缩文件，
   识别到缺分卷/缺密码会在条件变化后自动重试）——**这是"零操作"体验的终极形态**，
   也是我们 App 可以做的差异化场景（手机下载目录监控）。
4. 官方定位语值得记：「面向 Windows 的全自动化压缩包处理工具，**后台自动处理压缩包，无需手动解压**」。

`sunpack-passwords.txt`）。

**它的功能清单几乎就是我们的需求文档，逐字摘录**：

- **密码优先级**（原文）：
  > 密码优先级：虚拟密码（仅1个）>临时密码>从文件名中读取的密码>密码本中的密码（使用次数多的）>密码本中的密码（使用次数少的）
- **三种解压模式（原文）**：
  > 智能解压（逻辑参照Bandizip）/ 直接解压（不修改文件层级结构）/ 解压到同名目录（解压到压缩文件名称的文件夹）
- **解压后删除原始文件**、**支持分卷**（靠扩展名判断）
- **★ 解压后解散结果文件夹，用于处理嵌套的多层文件夹 ★**（= 我们说的「压平无意义嵌套」）
- **递归解压嵌套的压缩文件，直到解压结果中不存在压缩文件为止**
- 过滤规则、解压到指定目录
- 支持分卷示例：`xxx.7z.001 / xxx.part1.rar / xxx.part1 / xxx.z01 / xxx.zip.001 / xxx.bz2.001 / …`

**已知问题（原文，正好是我们要避开的坑）**：
> 1. 尝试解压 exe 文件时，可能无法正确地测试压缩文件的密码。
> 2. exe 已损坏时，可能无法正确判断是「文件损坏」还是「没有找到对应密码」。
> 3. 解压 zip 时会出现测试密码耗时较长的问题（7zip 会测试内部全部文件的密码）。
> 4. 默认使用本地编码解压，压缩文件编码与本地不同时，**文件名会乱码**。

**可学习点**：`密码优先级`这套显式排序值得直接照搬（并可让用户在 UI 里拖动调整）；
`智能解压/直接解压/解压到同名目录`三选一的分级；`解散结果文件夹`。

**吐槽点**：把 12 条功能铺在 README 里，用户得自己拼流程图；截图只有主/密码/设置页，**没有一张解压过程图**。

### 9.4 解TMD压 + 用户调研（论坛实证）

来源：小众软件论坛（appinn）讨论帖「各位选择解/压缩软件时，看中什么功能？」，
一位用户列的选型标准（**逐字，这是最真实的用户需求排序**）：

> **1.提取 2.智能解压（解压后删除） 3.批量压缩 4.密码自动解压和套娃解压**
>
> 7zip：免费无广告，右键打开提取方便。（主用）
> uzip：压缩解压多功能（7zip）
> OnlyUnzip：解压专用，密码自动解压。（7zip）
> **解TMD压：解压专用，密码自动解压。（7zip）**
> SmartZip：压缩解压多功能（7zip）
> bandizip：智能解压自动删除。
> Zip2Dir：关联右键，批量压缩zip自动删除。
> 查看和压缩主用7zip及其相关工具，**解压用bandizip智能解压**

另有帖子里的设计建议（逐字，几乎是我们 App 的需求描述）：
> 对解压缩软件的印象就是双击打开了个压缩文件之后能把文件释放出来就好，管它是什么。
> 对压缩包格式更是没有概念……「都什么东西（扩展名，什么扩展名）？」
> 面向大众……**最好内置在操作系统，次之抱大腿借热门软件暗渡陈仓；没那本事的话就兼容主流格式，
> 然后做到最漂亮、使用最简单，甚至视觉欺骗让人觉得你的速度最快；什么临时文件夹，
> 别让用户感觉到……** 为了满足某些老司机的需求，**增加个在弹出密码输入提示的时候多加一个
> "近期密码列表"，可以让用户选也可软件自己试，当然也要有一个"不保存本次密码"的复选框**。

**结论**：用户要的是 ①一键 ②自动试密码 ③套娃（嵌套）自动解 ④解压后自动删原包 ⑤智能决定目录结构。
**这五条恰好全是我们伪装包场景的刚需。**
另外「解TMD压」被隐写者 README 明确列为**能从开头扫描 MP4 隐写文件的手机端解压软件**
（v3.x 起），说明**中文圈已经存在「伪装包专用解压 App」这一品类**，但它的界面资料在公开渠道极度稀缺
（English 搜索结果全被 ZArchiver 占据）——这本身说明**这个品类的界面设计还没被做出来**。

## 11. 给我们手机端界面的 10 条具体建议

前提：Flutter/Android 优先，目标用户是「不会用 WinRAR、看不懂报错」的资源党。
以下每条都对应上文某个竞品的**实测细节**，不是泛泛而谈。

**1. 主界面用「ZArchiver 骨架 + 我们的一键按钮」，不要做上传区/向导。**
顶部工具栏 = 左侧返回/抽屉 + 中间路径面包屑（点击弹「常用位置：下载 / 百度网盘 / 夸克 / 最近解压」）
+ 右侧搜索、排序、更多。下面是占满剩余空间的文件列表，右下角 FAB。
**FAB 语义固定为「⚡ 一键解伪装解压」**——不要学 ZArchiver 让 FAB 随模式变形（它的 FAB 有
`+`/粘贴/其他三种含义，官方文档不得不专门解释一段）。

**2. 列表项采用「左图标 + 中文件名 + 下方元信息 + 右侧大小」的 ZArchiver 布局，
但把「识别结果徽章」加在文件名前面。**
ZArchiver 的行结构实测是：图标 → 文件名（文件名下方是修改日期）→ 右侧 `<DIR>` 或大小。
我们在文件名左侧加一个小徽章，把**识别结果前置**（这是竞品全都缺的即时反馈）：
`🎭 伪装包`（识别出 MP4/JPG 里藏了压缩包）/ `📦 分卷 1/5`（缺卷时变红 `📦 分卷 3/5 ⚠缺2`）/
`🔐 加密` / `🎬 普通视频`（已判定不是伪装包，灰显降低误点）。
依据：隐写者拖动 mp4 后立刻显示 `XXX.mp4 - 6m:14s - 35.69 MB`，即时识别能建立信任。

**3. 点按 vs 长按的双菜单，完全照搬 ZArchiver 的分工。**
- **点按** → 底部 BottomSheet（标题显示文件名），最上面第一个高亮的必须是
  `⚡ 一键解伪装解压`，下面是 `仅解压（不处理伪装）` / `查看内容` / `测试是否损坏` /
  `解压到...` / `复制密码` / `重命名`。
- **长按** → 另一套菜单：多选 / 复制 / 移动 / 删除 / 重命名 / 详情。
- 依据：ZArchiver 点按=`View/Extract here/Extract to…/Test/Compress`，长按=`copy/move/remove/rename`。
  **主操作点按即达**，文件管理收进长按，避免点错。

**4. 用「智能解压」三条规则做默认输出策略，并把规则显示给用户。**
后台逻辑照抄 Bandizip：
`包内只有一个文件 → 解到当前目录`；`包内所有文件都在同一个顶层文件夹 → 解到当前目录，
复用该文件夹名`；`否则 → 新建 <压缩包名>/ 放进去；重名则 <名字> (2)`。
UI 上在解压前的确认卡里写一行灰字：`将创建「movie/」文件夹（包内含多个散文件）`，
点击可切换为「不创建文件夹」。依据：Bandizip 官方三条规则原文 + OnlyUnzip 把它列为对标项。

**5. 解压执行页用「顶部栏形变」而不是全屏模态：顶部变成进度条 + 可折叠日志。**
- 顶部原本的工具栏原位替换为：`[←] ────▓▓▓░░ 62%  movie.7z.003 → movie.part2  ── [⌄]`
- 右端一个 `⌄` 把日志抽屉下拉（默认收起），再点 `Hide` 允许**后台继续跑并回列表看别的**。
- 依据：ZArchiver 的粘贴模式「工具栏变化 + FAB 变形 + 进度窗口带 Hide」，
  以及 Bandizip 进度窗口会显示**当前文件名 + 已用/剩余时间**。
- 加一条竞品没有的：**显示速度**（Bandizip 和 7-Zip 都不给速度，而大文件解压时用户最想看这个）。

**6. 密码环节做成「卡片式过程可视化」，绝不明文打印密码、绝不猜谜菜单。**
- 密码输入卡：输入框（带眼睛图标切换明文/密文，照抄 ZArchiver `Password: [Enter password] 👁`）
  + 一行可点的 `近期待用密码` chips（来自密码本，按成功次数排序——照抄 OnlyUnzip 的优先级：
  `虚拟密码 > 临时密码 > 文件名提取 > 密码本（使用次数多）> 密码本（使用次数少）`）
  + 一个 `☐ 不保存本次密码` 复选框（论坛用户明确点名要这个）+ 主按钮 `开始`.
- 自动试密码时**不要**像 Complex-unzip-v2 那样 `🔐 Trying password 尝试密码: 123456` 明文刷屏。
  改为：`正在尝试第 3/12 个密码…`，右侧一个 `查看` 展开才显示打码值 `12****`。
  依据：v2 源码逐字确认它明文打印密码与成功密码，这是**真实泄露**。
- **绝不 `clear()` 掉用户看过的内容**（v2 干了这件事，用户会恐慌）。历史只追加、可滚动。

**7. 报错必须给「可能原因 + 下一步动作按钮」，而不是一个红叉或一句「失败」。**
每个失败项出一张卡片，照抄 v2 的「可能原因清单」并升级为可点动作：
```
⚠ movie.rar 解压失败
   可能原因：缺少分卷 / 密码未找到 / 文件损坏
   ● 缺 movie.rar.part1 (已找到 part2-5)   → [ 手动指定缺失分卷 ]
   ● 已试 12 个密码均失败                  → [ 手动输入密码 ] [ 补充分卷后重试 ]
   ● 文件可能损坏                          → [ 复制诊断信息 ]
   原文件已保留在 原目录（未被删除）          → [ 打开所在目录 ]
```
依据：v2 有「可能原因」文案但只是静态文本；TR-Supowe 把失败包静默丢进 `_failed_archives`
让用户找不到——**失败产物必须有明确落点和二次入口**。

**8. 批量完成后弹「结果卡」，照抄 Sunpack 的 Toast 三段式，并补上失败入口。**
```
✅ 解压完成
   48 个压缩包成功 · 2 个失败 · 用时 4 秒
   [ 打开输出目录 ]   [ 查看 2 个失败 ]
```
依据：Sunpack 的 Windows Toast 实测文字为 `解压完成 / 48 个压缩包成功，用时 4 秒 /
[打开输出目录]`——**一条通知说清一切，不打断用户**，这是全调研中最干净的完成态设计。
我们比它多一个「失败入口」，因为我们的场景失败率更高。

**9. 安全默认值三件套（每一条都有竞品反面教材）。**
- **原压缩包默认移入回收站 / 软删除**，而不是永久删除。
  反面教材：ZArchiver **没有回收站**（官方原文自认 `Files and folders are deleted
  permanently. There is no Trash folder`）；7-Zip 直接删。
  → 做成「设置 → 解压后处理原包：移入回收站(默认) / 保留 / 永久删除」，并把 `永久删除`
  放在删除确认的二级里加一句红字说明。
- **失败时绝不删除任何输入文件**（v2 这条做得好，保留）。
- **目录内不自动解压以生成预览**（照抄 PeaZip 的安全原则：未明确请求不解压任何内容），
  预览只读文件头/元数据。

**10. 深色主题为默认 + 12 个一级控件之内 + 全中文动词表。**
- 深色默认（ZArchiver 实测就是深色主色），配 4 个语义色而不是彩虹：
  `成功=绿 / 进行中=蓝 / 警告=黄 / 失败=红`，**这套色板直接沿用 v2 已定义的
  ✓绿 / •蓝 / ⚠黄 / ✗红**，保证我们 CLI 与 App 视觉语言一致。
- 主界面一级控件不超过 12 个（反面教材：隐写者主界面平铺 11 个元素 + 底部 4 个按钮，
  没有视觉焦点，用户第一眼不知道该点哪）。**我们的第一屏只应该有一个最强入口：
  那个大 FAB。**
- 动词表统一（用大众词，不用 7-Zip 的工程词）：
  「解压」不叫「提取」；「解伪装」不叫「修复」；「分卷」后面永远跟 `1/5` 这样的进度；
  「一键解伪装解压」是唯一允许出现的「一键」四字组合（其余按钮都要能一句话说清做什么）。

## 12. 竞品都做得不好、我们能做得更好的 5 个地方

**① 「为什么失败 + 下一步做什么」没人做。**
所有竞品要么只给一行红字（v2 的 `❌ Wrong password 密码错误: 123456`），要么把失败文件
静默隔离（TR-Supowe 的 `_failed_archives`），要么直接抛 Python 异常字符串（TR-Supowe 的
`[ERROR] 读取密码文件 'x' 时出错: {e}`）。**没有一个竞品告诉用户「你缺 part1，去把 part1
一起下载下来」**——而缺分卷是伪装包最高频的失败原因。
→ 我们做**可执行的失败卡**：明确指出缺哪一个分卷、缺哪个密码、建议去哪里补齐，
每个原因配一个按钮（见建议 7）。

**② 手机端的「批量 + 自动试密码 + 递归解套娃」是一个空位。**
逐条核实：ZArchiver **没有**自动试密码、**没有**递归解嵌套、**没有**智能解压；
Bandizip **没有**自动试密码、**没有**递归；
Complex-unzip-v2 / TR-Supowe / Sunpack 有这些能力，但**全是 Windows（或 CLI）**。
中文圈 Android 上唯一被点名的「伪装包专用解压 App」（解TMD压 v3.x）**公开界面资料几乎为零**。
→ 我们做**手机端第一个「伪装包全自动解压」App**：丢进去→自动识别伪装→自动收集分卷→
自动试密码→递归解套娃→智能压平目录→结果卡。这六个动作在手机上目前**没有任何一个 App 全做到**。

**③ 完成态没人做对（除了 Sunpack 的 Windows Toast）。**
v2 是满屏绿色横幅 + 表格（终端里看得见，手机上不可用）；Bandizip 是进度条 100% + `Close`；
ZArchiver 什么都不给；隐写者是日志滚一段。
→ 我们做**手机端最好的完成卡**：结果标题 + 量化数字（成功/失败/用时/省下的空间）
+ 两个直达按钮（打开输出目录 / 查看失败项）+ 一句可复制的分享文案
（隐写者 README 里那段 `解压方法：用 WinRAR 改 MP4 后缀名为 ZIP 然后解压` 说明模板，
正好可以做成「解压方法一键复制给对方」的按钮——**这是这个圈子里真实存在的社交动作**）。

**④ 密码管理停留在「一个 txt 文件」的水平，且明文泄露。**
v2：`passwords.txt`，且**终端明文打印每个尝试的密码和成功密码**；
TR-Supowe：`0_temp.txt` / `1_all.txt` / 自建 txt，**程序自动往里写，用户不知道写了什么**；
OnlyUnzip：password 存 **pickle 未加密**（作者自述）；
ZArchiver/Bandizip/7-Zip：根本没有密码本。
→ 我们做**手机端密码本**：① 加密存储（不能是明文 txt）② 每个密码显示「成功次数 / 最近用于哪个包」
③ 支持从文件名/压缩包注释自动提取 ④ 支持「本次不保存」⑤ 一键导出/导入成 txt
（保持和「解TMD压」等工具格式互通——隐写者已经证明这种互通有价值）。

**⑤ 中文界面与中文文案没人真正做好（除了 Bandizip）。**
- Complex-unzip-v2：中英并排双语的每一条提示（可读性差，一行太长）。
- TR-Supowe：中文控制台但错误信息是 Python 异常。
- ZArchiver：官方只有英/俄文档，中文靠社区教程。
- PeaZip：**中文官网首页放的是英文界面截图，还带第三方水印**。
- 7-Zip：中文界面但用「提取/固实压缩/压缩后大小」这类工程黑话。
- 隐写者：窗口标题中文、右键菜单英文 `Steganographer`、目录名 `SteganographierGUI`（拼错），
  品牌名三套写法。
→ 我们做**单一中文品牌名（杨三海解压 / yshjy）+ 全中文动词表 + 中文界面截图当应用商店第一张图**，
并且**把「伪装包」这个词本身做成产品语言**（`🎭 伪装包` 徽章、
「这不是视频，是一个伪装包」这类一句话解释）。
依据：这个圈子的用户连「后缀名」是什么都要先搜一遍（隐写者 README 开头第一句就是
**「请确保在理解"后缀名"这个词含义的前提下观看以下教程，如不理解，请首先搜索『如何改后缀名』」**），
说明**用词和教育成本就是这个品类的核心体验**。
