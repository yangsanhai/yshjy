## 一、🔴 最劲爆的发现（原作者的 bug 级情报）

### 1. 隐写者的 ZArchiver 模式，视频**根本播不了**
- 噪声写入代码（`Steganographier.py` L2301-2323）**缩进错了**，落在 `while` 原子遍历循环体内（AST 已确认）
- 后果：噪声块被插到**每一个顶层原子之后**（连 `mdat` 之前都有），而 `stco/co64` 只补偿了 `free` 原子的长度
- 实测产物：`ffmpeg` → `moov atom not found`（非 faststart）/ `header damaged` rc=69（faststart）
- **即：ZArchiver 模式的文件，视频部分已被破坏**，但仍能解压（7z / 本程序读端均成功）

### 2. 两种模式的真实取舍（这解释了一切）
```
模式A 普通 mp4          [外壳逐字节原样][free 8B][随机pad][ZIP]
  → 视频完美播放 ✅    WinRAR 能解 ✅    zarchiver 解不了
模式B mp4(zarchiver)    [ftyp][free(含ZIP)][原第2个atom][噪声]…
  → 视频已损坏 ❌      改 stco/co64     zarchiver 能解 ✅
```
**没有任何一种模式能同时满足"视频能播 + 所有解压器都能解"** —— 这是它的根本缺陷，也是我们的机会。

### 3. 其他原作者的坑（我们要修）
| 坑 | 后果 |
|----|------|
| 密码本读端做 `ascii'ignore'` | **中文密码被吞掉**（用户密码永远试不对） |
| `reveal_file` 无返回值 | 批量模式成功率**恒为 100%**（假成功） |
| zarchiver 读端失败**静默回退** | 用户看不到真正原因 |
| `sanitize_path` 有 Zip Slip 隐患 | 恶意包可写到目录外 |
| 整段载荷读入内存 | 大包 OOM |
| 它**不生成分卷**、不生成说明书 | 资源里的"分卷说明"都是**发布者自己加的** |
| 封面默认是 `cover_video/` 里的 **Rick Astley** | 😂 never gonna give you up |

## 二、🎯 提取机制：我们怎么解（技术核心）

### 4. 「整个 mp4 当 ZIP 打开」为什么成立
Python `zipfile` 内部会算前置数据偏移：
```
concat = ECD_LOCATION − size_cd − offset_cd      # ECD_LOCATION = EOCD 在文件里的位置
每个 local file header 偏移 += concat
```
**前提：EOCD 必须落在文件尾 64KB+22 的窗口内** → 所以模式 B（free 内嵌）不满足，必须另设切片路径。
**Rust 版必须自己算 base**（zip2 不会代劳）。

### 5. 7-Zip `-t#` 的真正秘密（这就是"为什么要加 #"）
- 普通打开有硬限制 `kMaxCheckStartPosition = 8MB`（`OpenArchive.cpp:45`）→ **看不到 119MB 处的内嵌 ZIP**
- `-t#` **跳过该限制扫到 EOF**，并以 `searchLimit=0` 做**弱判定**，把 ZIP handler 直接摆到 Local Header 上
- 从而触发 ZIP 的 **LOCALS-CD-MODE 兜底**（`ZipIn.cpp:2731`）：**完全不看中央目录，纯靠 Local header 重建目录！**
- 分段算法：2 字节 u16 哈希表搜 magic 签名 → 试开 → 取 handler 报的 `PhySize` 作为段长 → 跳过

### 6. 7-Zip 的隐藏子参数（原先不知道）
```
-t#:e   /  -t#:a   /  -t#:r   /  -t#:s<size>
```
子选项控制扫描行为（含 size 参数）。

### 7. ⭐ LOCALS-CD-MODE = 救援模式的现成方案
"没有中央目录也能解压" 这个能力 7-Zip 已经实现 —— 我们做"救援模式"（损坏包抢救）时直接照抄这个思路：**扫描 local header 重建目录树**。

## 三、🧰 Rust 库的真相与坑（决定我们的技术选型）

### 8. zip2（zip-rs 9.0.4）
- ✅ **好消息**：它读成员**只用 CD 里的 compressed_size，从不读 local header 的尺寸** → 我们遇到的"local 与 CD 尺寸差 2355200 字节"**对它完全无影响**
- ⚠️ **零容错**：CD 记的 local header offset 不校验，直接 seek 要求 `PK\x03\x04`，不对就报错
- 📐 **ZIP64 偏移推导路径**：用「**实际 EOCD64 位置 − locator 声明值**」，而不是 CD → 正好对应我们的 `Δ = C − D64` 算法
- 🔧 `ArchiveOffset::Known(n)` 在 ZIP64 下被 locator 钉死，**不是自由参数**
- 🔑 **必须显式开 `legacy-zip` feature**（ZipCrypto），中文圈资源常用
- 建议方案：自研解析算 Δ → 用「8 字节 locator 补丁 + 尾部窗口虚拟 reader」喂给 `ZipArchive::new`，既修正偏移又保留它的解压/AES/并行能力

### 9. sevenz-rust 的真相（重要！）
- ⚠️ crates.io 上的 `sevenz-rust 0.6.1`（dyz1990）**仓库已无法访问**；活跃的是 **`sevenz-rust2`**（v0.24.0）→ **Cargo.toml 必须写 `sevenz-rust2`**
- ✅ **7z 没有总长度字段，但可精确推导**：
  ```
  总长 = 32 + NextHeaderOffset + NextHeaderSize      # 实测 bit-exact
  再用 CRC32(12..32) == u32@8 校验 → 扫描假阳性 ≈ 2⁻⁶⁴
  ```
- ✅ **7z 分卷是裸字节切分**（`.002` 连签名都没有！）→ 我们**只需实现多文件拼流的 Read+Seek**，不需要任何特殊逻辑
- ✅ 支持 AES-256+SHA-256（含 `-mhe=on` 头加密）、**中文密码**（内部 UTF-16LE）、LZMA/LZMA2/PPMd/BZIP2/BCJ/BCJ2
- ❌ **坑**：`Archive::read` 硬编码 `seek(0)` → 非零偏移（内嵌 7z）**必须自己包 Window**
- ❌ 库自带"头部损坏恢复"是**坏的**（源码用 `?` 而非 `continue`，12/12 归档全失败）
- ❌ 内存上限 `MAX_MEM_LIMIT_KB = usize::MAX/1024` ≈ 没有 → 恶意 LZMA2 字典可 OOM，且无 API 可调（**我们要自己加限制**）
- ⏱ 密码枚举成本 **121 ms/候选**（numCyclesPower=19 → 524288 轮 SHA-256）→ 自动试密码**必须限制候选数**
- 💡 内容加密的归档：**空密码就能列目录**（0.06 ms），要先列表再问密码

## 四、🔍 格式嗅探的最佳实践（XADMaster / unar）

### 10. 核心机制
- **有序解析器表**，逐个问 `recognize...`，**首个返回 YES 者胜出**；表顺序刻意分组（Common → Mac → 少见 → **需要重活的** → **过于贪心的**）
- 一次预读 `maxheader = 512KB` 分发给所有候选

### 11. ⭐ 值得偷师的四招
| 招 | 说明 |
|----|------|
| **浮动签名组** | 签名允许出现在文件开头 **1MB 以内任意位置**，多个命中时取**最小偏移**仲裁（缺省 1MB 阈值） |
| **EOCD 分块反向扫描** | 64KB 块 + **20 字节重叠**（因为 zip64 locator 正好 20B，块边界会漏）—— 扫到文件开头 |
| **识别期异常一律吞掉** | `@try/@catch` 当成"不匹配" → 允许写**贪心而脆弱**的识别器（架构哲学：识别器可以大胆猜） |
| **异常上报钩子** | `reportInterestingFileWithReason:` —— 专门给"可疑/异常"打报告的埋点通道 ← **正是我们需要的** |

### 12. 密码机制
- **拉取式**：`archiveParserNeedsPassword:` 回调，**引擎不含爆破**
- 但提供廉价早失败校验：ZipCrypto check byte = `CRC32>>24` 或 `localDate>>8`；AES 用 PBKDF2-HMAC-SHA1 1000 轮

## 五、✅ 由此定下的技术决策

### 扫描引擎分三路（覆盖所有已知藏法）
```
路1  尾部 EOCD + concat 偏移修正     → 模式A（尾部拼接）
路2  ftyp 后 free 原子直读            → 模式B（free 内嵌）
路3  LOCALS-CD-MODE（扫 local header）→ 救援模式 / 目录表损坏
```

### 关键实现原则
1. **自己算基准偏移**（zip2 / sevenz-rust 都不会代劳）
2. **分级预读**：先 4KB 过便宜签名 → 进入昂贵探测器才补到 512KB/1MB
3. **识别器可贪心**：异常 = 不匹配，不要因某个探测器报错就整体失败
4. **密码候选要限量**（7z 每候选 121ms），并做 **GBK/Big5/UTF-8 多编码尝试**
5. **内存必须有上限**（7z 库没有，我们要加）
6. **打包端要修掉原作者的两个坑**：
   - 噪声写在文件尾（不要插进原子链）→ **保证封面视频能正常播放**
   - 密码本不要 `ascii'ignore'` → **支持中文密码**
